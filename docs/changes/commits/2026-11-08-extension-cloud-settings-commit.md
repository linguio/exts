# 将扩展设置统一保存到账号：交付记录

## 对应工作项

- [Issue](../issues/2026-11-08-extension-cloud-settings-issue.md)

## 预期交付边界

每用户一行的服务端设置、读取和单字段保存接口；扩展 Theme、Media Download、Clear History 及相关后台触发复用当前账号的本地副本，登录与启动时从线上刷新。按接口成功结果反馈并更新副本，不迁移旧值，不保留本地 `version`，不影响其他本地业务数据。关闭最后一个窗口时不等待接口，完整退出浏览器时仍尽力执行。

## 实际交付

按最终确认开放未登录本机设置：首次使用内置默认值，修改后只写本机；登录后仅使用云端记录或云端默认值，不导入离线设置；退出清空 Exts 本地数据后回到未登录默认值。本机和账号副本共用 `settings` 业务结构，账号副本带 `userId` 区分。

按验收反馈调整账号重置：退出或重新登录只清理扩展本地状态并写入 Telegram 目录待清理标记，不再打开、逐页等待或依赖 Telegram Web。已打开页面在标记变化时自行中止扩展下载并清理目录；未打开时下次进入页面先清理，再启用扩展下载入口。Telegram 网页响应不再决定账号操作结果。

后续 `0003` 迁移补充 `created_at`：新记录使用数据库当前时间，既有记录因无真实创建时间，以原 `updated_at` 近似回填；该字段不进入设置接口响应。

新增 `public.user_settings` 迁移与独立 Settings 读取、单字段保存接口；无行读取返回默认值，首次成功保存建行，服务端按已验证账号读写。扩展后台复用现有 Axios 业务请求层，将接口返回的三项设置写入带 `userId` 的 `settings` 副本，去掉本地版本和旧格式读取；同一后台实例合并并行读取，保存任务串行处理以免旧结果覆盖新值。设置页直接展示设置项，不包含账号判断或登录入口；成功保存才更新 UI 和副本并显示成功提示。

Theme 保留现有同步首屏偏好与退出清理；Media Download、Telegram 及 History Cleaner 沿用共用 Settings 订阅。浏览器启动先尝试线上刷新后执行清理，最后窗口关闭直接读取同账号副本与本机权限，不在关窗路径等待设置接口。完整退出浏览器时，异步清理仍属于尽力执行。

## 用户验收

用户于 2026-11-08 确认验收通过；以下步骤保留作复现参考，代理未独立完成 Chrome/Edge 交互验收：

1. 当前 API 配置指向的 Neon 数据库已应用 `0002_user_settings.sql` 和 `0003_user_settings_created_at.sql`；刷新 Newtab 并重试 Settings。扩展开发构建需加载 `dist/dev/chrome-mv3-dev-stable`，本地 API 需保持运行。
2. 未登录打开 Settings，应直接看到设置项，没有任何账号提示或登录按钮；修改 Theme、Media Download、Clear History 后重新打开仍保持本机选择。通过现有 Account 入口登录后应以该账号云端值覆盖；云端没有记录时三项均显示默认值，不继承离线选择。分别修改三项，每次成功后应提示“已保存”，重新打开设置仍保持云端选择。
3. 已登录时关闭 API 后尝试修改设置，应提示失败且控件、主题和副本保持原值；重新连接 API 后重试成功。退出后应回到未登录默认值，且旧本机设置不恢复；重新登录同一账号应恢复云端设置，切换账号不得显示上一账号副本。
4. Clear History 开启时先授权 `browsingData`；拒绝权限不应显示保存成功。用专用 Chrome/Edge 配置文件验收最后普通窗口关闭和下次启动的历史清理，勿用日常浏览器数据。Telegram 页面确认下载入口随 Media Download 开关变化；断网时只沿用当前账号已有副本。
5. 保持 Telegram Web 标签打开时退出 Exts，网页不应被重新加载或新开标签，扩展下载入口应停用；重新登录后不应沿用退出前选的目录。没有 Telegram 标签时退出也应完成，下次打开 Telegram Web 后应先清掉旧目录再启用下载入口。
