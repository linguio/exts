# 统一登录初始化与退出重置：交付记录

## 对应工作项

- [Issue](../issues/2026-11-06-extension-session-reset-issue.md)

## 预期交付边界

登录前统一本地重置、退出清除扩展自有持久化数据及运行状态（含下载记录、Telegram 目录句柄和在途下载）、多页面重建和失败处理。已下载到电脑的文件及第三方网站数据不在清理范围；数据库连接池参数调整另列工作项。

## 实际交付

后台统一会话代次与清理锁：重置时取消 Activity、等待既有设置/记录写入，以请求携带的会话代次拒绝旧操作；同一账号重新登录也换代次。主动登录先清空旧业务与认证状态，退出先停下载并清理业务状态，再执行认证退出和凭据清除。成功后向所有 Newtab 同步新账号与代次，Activity 清空旧展示并重新请求；页面和当前视图保持挂载，不调用 `location.reload()`，也不整体重建组件树。失败不报成功，保留错误提示并同步可重试状态。

`chrome.storage.local` 清空设置和下载记录；Newtab 清掉主题首屏偏好；OIDC 存储清空旧用户及临时状态。Telegram 已打开页面先中止下载和目录操作，再由 MAIN 世界定向清空 Exts 专用目录库；无页面时临时创建非活动标签页，完成后移除。不清除 Telegram 整站数据或磁盘上已完成的文件。

## 验证与限制

扩展全套 28 个测试文件、122 项测试通过；TypeScript 类型检查及 WXT 生产构建通过。构建仍提示现有 `theme-init.js` 非模块脚本和较大 chunk 警告，本项未修改相关资源。用户曾报告“会话已重置，请刷新页面”和 Activity“加载失败”；修正为请求代次校验并对切换期间取消的请求不弹错误后，尚未在真实 Chrome／Edge 复验。临时 Telegram 页、跨页面广播、文件句柄和在途下载也未由代理实际验证；未清理日常浏览器数据。API 连接池 60→300 秒尚未执行，已列为独立后续事项。

## 用户验收

用户于 2026-11-07 表示验收通过并请求本地提交；该消息到达时，闪烁和误拒绝修正仍在实施。最终 diff 展示后，用户再次明确要求 `commit`，批准本地完结；最终代码的真实浏览器复验未单独记录。以下保留可复现的验收步骤：

1. 运行 `pnpm ext:dev`，等待成功发布后加载 `dist/dev/chrome-mv3-dev-stable`，打开两个 Newtab，其中一个切换 Studio。
2. 在 Telegram 选择目录并产生一条下载记录；切回 Newtab，退出账号。预期所有 Newtab 回到默认未登录状态，设置、记录与主题偏好恢复默认；已保存文件仍在电脑上。
3. 不打开 Telegram 页面再次登录同一账号，检查活动图表重新加载而非沿用旧展示，下载记录为空，目录首次使用需要重新选择；在同一浏览器配置文件重新检查 Telegram 原有网站数据未被整站清空。
4. 在 Telegram 正在保存文件时退出，预期下载停止、没有新的完成记录；若目录或认证清理失败，界面不能提示退出成功且可直接重试。跨账号重复第 2–3 步，确认没有上一账号本地数据。登录和退出不得触发整页刷新或“会话已重置，请刷新页面”及取消请求引发的“加载失败”。
