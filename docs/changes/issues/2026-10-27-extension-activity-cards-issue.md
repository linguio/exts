## 背景与目标

当前首页打卡卡片在 JLPT / Workout 之间切换，读取两份本地模拟 JSON，展示最近 24 周日历。希望改为学习、运动、编程的日常时长录入与统一统计。

## 已确认方向与拟定范围

- 上方新增两张文件夹大小的卡片：左侧 Todo 时长录入，右侧本周进度圆环；下方一个统一的日历／图表卡片。
- 切换项由活动类型改成「日历 / 图表」。日历 hover 展示当天学习、运动、编程时长。
- 图表展示当周数据：左侧每天一根柱，内部体现学习、运动、编程的构成；右侧饼图展示本周各项时长。
- 不再维护预填的假数据 JSON；旧模拟数据拟删除，重新设计。先以变量／内存状态实时联动，修改后立即可见。删除与实现须在后续明确批准的范围内进行。
- Todo 每行采用 Checkbox + 输入组合；组合内包含活动图标、分钟输入和完成度后缀。
- 每项预设不同的最高分钟数，例如 60、120、600；输入不能超过该项最高值。
- 勾选表示该项完结，禁用输入；取消勾选后才可修改。勾选不表示必须达到最高值。
- 完成度后缀使用颜色分级，与日历共用一套全局颜色 Token，不能只定义在日历内部。
- 数据与界面分离：Newtab、未来 Studio 的界面通过同一业务数据接口读写／订阅，不把设置视图在模块之间挂载。

## 待讨论，不能视为已批准

1. 是否先做界面与空状态，再做内存录入联动，最后单独做持久化；用户尚未选择实施顺序。分别能独立交付时，应拆成后续主 Issue，不在本草稿无限扩充。
2. 业务模块是否改名为 `activity`，日历视图叫 `calendar`；共享颜色是否改名为 `--activity-level-*`。这些是代理建议，用户尚未确认。
3. 学习、运动、编程是否固定；图标、最高分钟数在哪里配置，是否放入 Studio；Studio 的范围尚未确认。
4. 最低时长是否需要；代理建议不设门槛，但尚未获用户明确确认。空输入、0、整数限制及无有效时长时能否完结待定。
5. 输入过程是否只预览，勾选后才正式计入统计；解锁时保留上次确认结果，还是所有视图立即跟随编辑值。不能把实时预览与已确认记录混为一谈。
6. 完成度后缀只是展示，还是可点击按钮；代理建议无动作时不用 Button。具体官方组件需实施前核对。
7. 分级阈值、日历每日总等级、本周圆环计算方式；不能将代理提出的 0 / 不足 50% / 不足 100% / 100% 当成已批准规则。
8. 最高分钟数修改后，历史完成度按旧上限还是新上限计算。
9. 一周从周一还是周日开始；是否保留最近 24 周布局；堆叠柱用实际分钟还是归一化比例。
