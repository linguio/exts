# 动态居中 Newtab 上半区并统一文件夹行距

## 背景

原 Newtab 上半区左栏占满剩余空间，右侧卡片靠近页面右边，不能将左右实际内容作为整体居中。左侧文件夹包含预览框和下方名称；用户在实际查看后要求重新调整名称与行距比例，最新批准名称上下留白对称的 8px + 16px + 8px 方案。

## 目标

根据容器可用宽度及左侧实际内容动态确定列数和占用宽度，将左右区域整体水平居中，多余空间平均留在两端；调整浏览器窗口大小时实时生效。左侧换行后，名称上下各保留 8px、单行行高 16px，两行预览框边缘之间总共 32px。

## 范围

- 用户在本轮布局验收中最新批准“48”：Dock 中间分割线高度从原有 64px 改为 48px，保持垂直居中、原有 1px 宽度与主题颜色；此项作为当前布局验收补充。
- 不要求用户指定整体最大宽度或固定列数。根据上半区可用宽度，扣除右侧固定列宽及中间 24px，再结合当前文件夹数量、现有预览框宽度和横向 24px 间距，确定左侧一行可容纳的数量及实际列宽；不生成超出内容数量的空列。
- 使用 ResizeObserver 监听外层可用空间变化，首次显示及用户手动缩放浏览器窗口时重新计算；监听可用空间而非计算后收缩的内容宽度，避免尺寸反馈循环。监听随组件卸载清理。
- 左侧按既有顺序自然排列，放不下时换行；以所有行中最宽一行的占用宽度确定左栏宽度，末行维持左对齐，不逐行单独居中或拉伸文件夹。剩余不足一列的宽度归入两端留白，不滞留在左栏与右侧之间。
- 右侧沿用现有固定列宽及尺寸来源，卡片只纵向排列，不压缩右侧列宽、不移至左栏下方。整体居中时右侧允许随整体位置移动，不要求固定在视口的某个横坐标。
- 左右内容顶部对齐，左右区域之间维持 24px；保留页面最少 24px 外边距、上半区与 Dock 的既有间距、左右独立滚动和底部 Dock 布局。极窄窗口不足以放下一个文件夹、分栏间距及右栏时，沿用区域内部溢出约束，不覆盖相邻区域或 Dock。
- 左侧文件夹横向预览框间距维持 24px；纵向按预览框边缘计，相邻两行之间总共 32px。名称上方 8px、固定单行行高 16px、名称下方至下一行预览框 8px；名称不得另加高度或行距，长名称单行省略，不撑高行。
- 仅调整 Newtab 页面布局及必要的文件夹名称样式；名称规则限制在本次首页场景，避免影响 Dock、预览和其他共用场景。实施时同步直接相关的现行 Newtab/UI 说明。

## 验收标准

- Dock 中间分割线高度为 48px，垂直居中，宽度仍为 1px；用户核对缩短后的视觉效果。
- 宽窗口能容纳全部文件夹时，左侧仅按实际内容占宽，和右侧卡片一起水平居中，两端留白相等，无需配置整体最大宽度。
- 连续拖动窗口宽度跨过换行临界点时，左侧自动增减列数并换行，整体重新居中，不出现多余空列；右栏保持固定宽度、纵向排列，不卡在原视口位置。
- 左右内容顶部对齐；最宽书签行与右侧卡片之间为 24px，文件夹横向预览框之间为 24px，末行左对齐。
- 发生换行后，两行预览框边缘之间总共为 32px；名称以固定 16px 单行行高位于其中，上下各 8px，长名称不会增加行高或推开下一行。
- 降低窗口高度时，溢出仍由左右区域分别内部滚动处理，内容不侵入相邻区域或覆盖 Dock；原有文件夹与书签功能保持可用。
- 用户在 Chrome 或 Edge 加载实施后提供的构建产物，分别执行宽窗口、连续缩窄再放宽、降低高度等操作核对以上结果；自动化检查通过不代表已完成视觉或交互验收。

1. 在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，加载或重新加载 `D:\GitHub\exts\dist\build\chrome-mv3`。本轮仅生成生产产物，原 `dist/dev/chrome-mv3-dev-stable` 没有更新。
2. 打开新标签页并拉宽窗口，检查左侧文件夹和右侧卡片作为整体居中，两端留白对称，左右之间为 24px，首行预览框与右侧卡片顶部对齐。
3. 连续缩窄窗口直至左侧出现多行，再放宽窗口；检查列数实时变化、末行左对齐、整体重新居中，右侧宽度不变并始终位于右边。若窗口不足以同时展示最小左栏和固定右栏，检查内容仍受各自区域约束、不侵入相邻区域或 Dock。
