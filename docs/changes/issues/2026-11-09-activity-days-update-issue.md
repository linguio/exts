## 已核对现状

- `activity_daily_records` 当前有 `(user_id, date)` 复合主键；`user_settings` 有 `user_id` 主键。两张表都有主键，但均无用户要求的独立记录 `id`，本 Issue 拟为两张表都补齐。
- Daily 目前用真实查询结果做当前页前端预览，尚无写接口；共用 QueryDataTable 有 `updateFn` 接入口，保存成功后可按当前查询刷新。
- 时长字段在数据库允许 NULL 与非负 INTEGER；现有前端 `inputMode="numeric"` 只提示键盘布局，不能阻止非数字键入或粘贴；当前空输入可映射为 NULL。

## 目标与范围

- 为 `activity_daily_records` 和 `user_settings` 分别增加服务端生成、永久稳定的 UUID `id`，迁移旧记录并各自改为主键；保留 Daily `(user_id, date)`、Settings `user_id` 的唯一约束，维持每日单条与每人单份设置语义。迁移前核对实际数据库版本、数据量、外键与索引依赖；迁移须保留现有记录、Settings 按 `user_id` 的 UPSERT 及 Daily 定时建行的冲突语义。
- Daily 查询及更新成功响应返回 `id`。Settings 真实记录返回 `id`；尚未创建设置行时仍返回现有默认设置，`id` 为 null，不为一次读取创建数据库行。设置更新仍按认证用户定位，不要求前端提交设置记录 ID。
- 不新增 `version` 或其他客户端版本字段。新增 `POST /api/activity/days/update`，JSON 请求体包含 `id` 与 `changes`。身份仅取已验证令牌，不接受客户端 `userId`；只能更新本人现有记录，不允许修改日期、不创建新记录。`changes` 仅允许五个时长字段，至少一项，每项必须是 0 至数据库 INTEGER 上限的严格整数；明确拒绝 null、负数、小数、布尔值、字符串及未知字段。响应使用现有成功/错误结构。
- 更新以 `id + user_id` 为条件，一条参数化 `UPDATE … RETURNING` 完成修改并返回记录；未命中一律按本人记录不存在处理，不暴露他人记录。PostgreSQL 自动持有被更新行的行锁，不另写公共锁方法、安装锁库或显式 `SELECT FOR UPDATE`。同时编辑不同字段时只提交改动字段，可保留彼此不同的修改；同时编辑同一字段时按数据库完成顺序以后写结果为准，不承诺冲突提示。
- Extension 的 Daily 查询响应接入 `id` 并以 `id` 作稳定行标识；编辑提交只发送相对打开时原值发生变化的字段，未改动的既有 NULL 不强制补值。用户主动修改的时长必须填写数字：输入过程仅接受 ASCII 数字（含粘贴），允许编辑中暂时为空，但 Save 对已改成空值的字段报错；0 合法。服务端独立执行最终严格校验。
- 将 Daily 从 `previewEdits` 切换为真实 `updateFn`；成功后按当前筛选、排序和页码重新查询服务端。普通失败保留 Sheet 草稿，不自动重试或伪造成功。
- Daily 查询失败时仍呈现表格空数据状态，不在内容区显示“查询失败”警报或原始连接错误；使用应用现有右下角 Sonner 错误 Toast，提示语使用简短中文。请求失败不可伪装成查询成功，保留可重新查询的路径与安全日志；该共性规则同步表格规范。

## 排除项

- 不新增记录、删除记录、批量更新或修改 Settings 的业务字段/交互；Settings 仅补独立 ID 与必要响应契约。不改变业务日期与用户归属；不对其他表格批量接入真实写接口。
- 不部署、推送或 Git 提交；实际数据库迁移须在迁移文件及目标库核对后执行。

## 已确认的关键决定

- Daily 和 Settings 均用独立 UUID `id` 作主键，并保留各自现有业务唯一约束；Settings 读取无持久化行时 `id` 为 null。
- 不加应用层/显式锁、不加 version；同字段并发更新接受后写覆盖，异字段使用局部补丁尽量保留双方修改。
- 本轮主动修改字段禁止提交空值；历史 NULL 允许原样保留，0 是合法值。

## 验收标准

- 两张表旧记录迁移后均有稳定唯一 `id`，原数据不丢；Daily 同一用户同一天仍不能重复，Settings 每人仍只有一份，原定时建行与设置 UPSERT 保持有效。
- 仅本人能用 Daily `id` 修改现有记录；未知/越权 ID 和非法数字得到明确错误，服务端不接受未授权字段。Settings 无记录时维持默认读取语义并返回 `id: null`。
- 同字段并发保存由数据库行锁串行执行，按完成顺序以后写结果为准；不同字段局部更新不覆盖对方未触碰字段；没有应用级锁或 version/409 冲突机制。
- Daily 输入不能录入非数字字符；暂时清空可以继续编辑，但不能作为修改结果保存；原有未改动 NULL 不被强制填写，0 可以保存。
- 保存成功后重新查询，显示服务端记录、`id/updatedAt` 与当前排序/筛选结果；失败保留草稿，取消仍不写入数据。
- Daily 查询失败时表格显示空数据，错误只经右下角中文 Toast 呈现，不出现占据表格位置的失败警报或原始连接错误；可通过 Query/Reset 重新发起查询。
- 用户在 Chrome/Edge 完成实际交互验收；代理只执行必要逻辑、契约和构建验证。
