# 按文件夹保存书签显示与密码设置

## 元信息

- 工作项：2026-10-30-extension-bookmark-folder-settings
- 状态：待批准
- 当前阶段：需求建档；功能尚未实施。
- 批准依据：用户要求将本轮书签文件夹讨论整理为 Issue 并提交到本地；本次批准仅覆盖建档和文档提交。
- 任务规模：设置与密码校验涉及持久化结构及访问边界，实施前需明确数据兼容和密码规则；拖拽可独立验收，不作为本项实施阶段。

## 背景

当前 Newtab 从 `apps/extension/src/modules/newtab/constants/bookmarks.ts` 读取静态书签。文件夹使用稳定 `id`，`blur` 控制默认模糊；缺省视为不模糊。EDU 密码在 `utils/bookmarks/folder-access.ts` 中固定为 `0000`，组件通过 `folder.id === 'edu'` 启用专用校验，未按文件夹保存密码设置。

现有 `chrome.storage.local` 按功能组织：`settings` 保存主题及功能设置，`downloads` 保存下载记录；后台共用串行读写与配置校验，页面监听变化。尚无 `newtab` 或 `bookmarks` 配置分组。

## 目标

允许用户右键文件夹调整模糊和密码设置，设置按文件夹稳定 ID 关联。文件夹改名或调整位置后仍保留同一份设置，不再为 EDU 单独写死密码逻辑。

## 拟实施范围（待用户审阅批准）

- 沿用按功能分组的现有设计，建议配置归入 `settings.bookmarks.folders[folderId]`；不调整 `mediaDownload`、`historyCleaner` 的结构或语义，不引入 `newtab` 页面分组。
- 静态 `.ts` 继续保存默认书签和默认模糊值；本地仅记录用户设置，读取时按 ID 合并，本地显式 `false` 同样覆盖默认值，不回写源码或复制完整书签数据。
- 通过官方 shadcn/ui Context Menu 提供模糊开关和密码设置入口；具体菜单、密码输入形式与修改流程在实施前确认，复用现有主题与通用组件。
- 密码配置随文件夹 ID 保存，取消 EDU 专用判断；持久化校验信息，不直接保存明文密码。解锁状态与输入中的密码仅保留为页面临时状态。
- 模糊与密码区分：单纯模糊允许点击显示；启用密码时先解锁。修改或移除已有密码需校验旧密码，此项规则仍待用户批准。
- 复用现有后台配置保存、校验、迁移和变更订阅机制；明确旧 EDU 固定码向新模型的兼容策略后再实施。

## 排除项与后续方向

- 本次只建档，不修改代码、依赖、配置、书签内容或产品版本，不安装拖拽库。
- 卡片不归入该配置；不改 Studio、下载、历史清理或主题功能。
- 文件夹拖拽排序与内部图标拖拽排序记录为后续独立工作项方向，待本项完结并获得批准后另行建档；顺序应基于稳定 ID 保存，不以数组位置关联密码。
- 是否允许图标跨文件夹移动尚未确认，不纳入范围；如需要，须设计书签归属的持久化，不能仅保存排序数组。
- 不做书签内容加密、云同步、导入导出、文件夹新建删除或多层嵌套；本项密码仅控制界面访问，不承诺数据保密。
- 官方组件目录目前无独立拖拽排序组件；官方 Dashboard 示例采用 dnd-kit。后续拖拽选型时重新核对官方方案和精确版本，不将第三方 shadcn 风格组件认作官方组件。

- 密码校验信息的格式、算法与迁移边界；实现前按实际风险补充必要设计，不直接沿用固定码。

## 验收标准（实施后验证）

- 用户加载 `dist/build/chrome-mv3`，右键任意文件夹修改模糊，当前页面立即更新；刷新或重新打开标签页后保留设置，其他文件夹不受影响。
- 未自定义的文件夹沿用静态默认值；用户关闭默认开启的模糊后，刷新仍保持关闭。
- 每个文件夹可独立配置密码；正确输入才显示内容，错误输入不解锁；修改或移除密码遵循最终批准的规则，EDU 不再依赖专用硬编码。
- 纯逻辑验证配置通过稳定 ID 关联，重排默认数组或改变名称不丢失设置；实际拖拽不属于本项验收。
- 主题、媒体下载和历史清理设置保持；多个新标签页按现有订阅机制更新配置，临时解锁状态不作为共享持久化配置。
- 视觉、菜单、焦点及拖动等交互由用户在 Chrome／Edge 验收；代理不新增此类自动化测试或假 DOM 环境。
