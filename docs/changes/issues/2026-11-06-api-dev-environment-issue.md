## 背景与目标

已有虚拟环境缺少新依赖时，API 在 Uvicorn 子进程导入阶段失败。让现有 pnpm api:dev 和 pnpm dev 自动完成 Python 环境准备，在启动服务前报告可操作的错误。

## 范围与排除项

- 范围：检查精确 Python 版本；缺少环境时创建；首次或 Python/两份依赖清单变化时安装 requirements-dev.txt；成功后保存摘要；检查 DATABASE_URL、NEON_AUTH_ISSUER、API_RESOURCE；保留现有启动方式和重载。
- 排除项：不升级依赖、不安装系统 Python、不覆盖 env、不执行数据库迁移、不更换工具链、不修改前端或线上环境。
- 规模：单一开发启动目标，沿用当前工具链；使用本 Issue 的 Todo 记录实施步骤，不另建 Spec、Plan 或子 Issue。

## 验收标准

- 首次启动自动创建虚拟环境并安装固定依赖；已有环境首次接入也会同步。
- 环境和清单不变时跳过安装；两份依赖清单任一变化均触发同步。
- Python 不可用、版本不符、安装失败或必要配置缺失时不启动 Uvicorn；安装失败不保存成功摘要，下次可重试。
- 配置检查与 API 使用同一 env 读取规则，仅提示变量名，不输出凭据。
- 用户在仓库根目录运行 pnpm api:dev，确认 Application startup complete，再刷新 Newtab；浏览器和真实服务验收由用户执行。
