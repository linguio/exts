## 背景与目标

Newtab 的 Download 目前是空抽屉。后续需要集中查看 TG 与 X 的下载记录，并通过随来源筛选变化的文件夹入口打开预设目录。本工作项只保存已确认的行为和实施边界，供后续独立实现工作项使用。

## 本次范围

- 记录 Download 抽屉的「全部 / TG / X」三个图标筛选入口；默认「全部」，混合记录按完成时间倒序。图标切换复用现有官方 ToggleGroup，品牌图标沿用现有资源。记录界面位于 `newtab/views/downloads/`，Dock 只组合入口。
- 记录存储使用 `chrome.storage.local` 顶层 `downloads` 对象，内部按 `tg.records`、`x.records` 分组；TG 和 X 各自负责下载，公共 downloads 模块负责记录读写，Newtab 负责读取和展示。具体记录字段、上限和操作在实施工作项确定。
- 顶部文件夹图标随筛选对应：全部打开 `~/Downloads/Exts Downloads`，TG 打开其 `Telegram` 子目录，X 打开其 `X` 子目录。点击时目录存在则在 Finder 打开；不存在则提示“文件夹不存在，请先运行 Exts Desktop 创建。”Desktop 不可用或通信失败时显示不同提示，不误报目录不存在。
- Desktop 正常启动时补齐根目录及 `Photos`、`Telegram`、`X` 子目录；已有文件和目录不删除、不迁移。点击 Newtab 文件夹图标不创建目录。
- Telegram Web 继续使用现有任意文件夹选择和页面侧媒体保存方式。预建目录只方便用户手动指定；TG 筛选下的图标始终打开预设 `Telegram` 目录，即使实际下载目标由用户改到了别处。
- 精确检查并打开指定 Finder 目录需要扩展与 macOS Desktop 的通信及返回状态；当前工程没有这条连接。实施前确定连接方式、安装与不可用时的反馈，不把媒体字节交给 Desktop。

## 排除项

- 本工作项不修改应用、扩展、权限、构建配置或下载行为；不创建目录或打开 Finder。
- X 下载尚未迁入当前 Extension，不把旧归档功能视为已接入；不承诺本次产生 X 记录。
- 不自动改变 TG 的保存位置，不强制 TG 使用预设目录，也不把预设目录误称为实际保存位置。
