## 背景与目标

原请求为检查用户和读取 Activity 分别建连，重复执行事务设置，已有数据库路径约 8 秒。当前通过公共连接池、启动准备、合并身份与数据读取、单次只读事务合批减少往返；用户反馈热请求稳定约 200ms。

用户期望完整请求最多 300ms。当前诊断样本 177–210ms，用户已反馈日常热请求表现；不将其扩展为所有冷启动、并发和故障场景的最大时延承诺。

## 范围与排除项

- 范围：API 公共连接池、资源准备、连接借还、多步事务/单次只读执行、Activity 仓储接入、相关行为验证及长期文档；本轮清理导入/排版、无用测试模拟和重复文档，不改变功能或资源策略。
- 前端：沿用 lib/api/client.ts 与地址配置，不增加包装，不修改 JSON 契约或 DevTools 展示。
- 保留：JWT 校验、用户不存在 401、本人数据过滤、日期/NULL/0/空记录、只读/读写、上海时区、语句/锁超时、SQL 错误回滚及事务所有权。
- 排除：不改数据库结构/数据、角色默认值、云端/部署、既有依赖版本、业务缓存、登录踢出策略或永久保活；不提交、推送或发布。
