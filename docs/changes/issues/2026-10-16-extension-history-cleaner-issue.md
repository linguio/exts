## 背景

当前扩展只有 Newtab 页面入口和 Settings Sheet 外壳，没有后台入口、清理权限或持久化设置。用户需要与 Newtab 独立运行的访问历史清理功能，同时集中在 Settings 配置。

## 目标

提供一个默认关闭的设置开关，启用后在当前浏览器配置文件启动和最后一个受支持窗口关闭时各清空一次全部访问历史，不要求打开 Newtab。

## 范围

- 新增 src/modules/history-cleaner，包含后台事件、设置读写、清理操作和设置区域；新增薄的 WXT background 入口进行注册。
- Newtab Settings 接入该模块的一个开关，不承载后台清理逻辑。
- 新增 storage 权限；按 Spec 推荐将 browsingData 声明为可选权限，启用开关时申请，拒绝后保持关闭。
- 仅清除当前配置文件全部访问历史；不清 Cookie、缓存、下载记录。
- 补充纯逻辑、配置与构建验证，并同步功能文档、UI 文档及 AGENTS 中的 Settings 范围。

## 验收标准

- 开关默认关闭，状态保存在本机，重开 Newtab 或浏览器后保持；拒绝清理授权时不启用，不因启用立即删除历史。
- 启用后，配置文件启动清理一次；关闭最后一个普通窗口或网页弹窗时尝试清理；仍有相关窗口时不清理。
- 未打开 Newtab 时后台仍能执行；worker 普通唤醒、扩展安装和更新不能被误当成浏览器启动清理。
- 关闭开关后停止后续自动触发；权限缺失时不执行清理；清理失败不伪报成功，不自动重试。
- 不影响 Cookie、缓存、下载记录与其他 Newtab 行为，不增加无关权限或依赖。
- 自动化只验证纯逻辑、配置、构建与必要边界；真实 Chrome/Edge 事件、授权、视觉及交互由用户实际验收，不能保证退出前清理完成。

## 用户验收步骤

1. 使用专用测试 Chrome/Edge 配置文件，避免删除日常访问历史。在扩展管理页开启开发者模式并加载 D:\GitHub\exts\dist\build\chrome-mv3；已有同路径扩展则重新加载，不打开 worker 调试器。
2. 打开 Newtab → Settings → Browsing history，确认开关默认关闭、界面随主题显示；开两个新标签页并打开 Settings。
3. 开启开关后，浏览器权限请求可能直接成功而不弹窗；预期开启且另一页同步。若浏览器实际提供并拒绝授权，预期保持关闭并显示提示。关闭再打开设置，状态仍保存；开启动作本身不删除已有测试历史。
4. 访问测试网站，在同一配置文件保留第二个普通窗口，关闭其中一个窗口；剩余窗口的历史页应仍保留测试访问记录，Cookie/登录状态、下载记录不受影响。
5. 关闭所有 Newtab 页面后继续访问测试网站，关闭最后一个窗口，再完整退出并启动浏览器；检查原测试访问历史已清空、开关仍开启，验证双向触发的最终效果。不要使用恢复旧标签页的结果来判断旧历史是否遗留；此步骤不能单独证明关闭阶段必定清理成功。
6. 关闭开关，重新访问测试网站并重复正常退出/启动，预期记录保留；原书签、Dock 菜单和 Settings 关闭流程正常。
7. 若浏览器提供撤销此可选权限的入口，撤销后应显示关闭并停止清理，可重新授权；授权拒绝和权限缺失分支已有 API 替身测试覆盖，不以必须弹窗或必须提供撤销入口为验收要求。检查失败提示、窄窗口和明暗模式的实际效果。
