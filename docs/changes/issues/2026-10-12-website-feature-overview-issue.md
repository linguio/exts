## 背景

官网需要一个简洁的产品功能概览，让访客知道 Exts 包含哪些模块、分别能做什么。用户希望入口位于 Changelog 旁边，页面参考 Changelog 的文字排版，不采用详细说明书或界面展示卡片，减少后续维护。

## 目标

新增独立功能介绍页，左侧切换功能分类，右侧仅以模块标题和一句话介绍展示已交付能力。

## 范围

- 导航新增“产品介绍”入口，紧邻“更新日志”，进入独立 `/features/` 页面；更新日志地址保持 `/changelog/`。
- 首页、产品介绍、更新日志统一使用 SiteLayout 装配 Header／Footer，统一固定高度、外层容器、正文预留与滚动条空间；首页保留原有主体布局。
- 产品介绍与更新日志共用正文框架，统一 720px 阅读宽度、标题、顶部间距和正文基础排版，时间轴与分类内容保留各自结构。
- 产品介绍与更新日志的页面标题、导航提示和无障碍名称统一使用中文；入口图标分别使用 BookOpen、FileClock。
- 两个入口使用同一个 Tooltip 组件，鼠标悬停或键盘聚焦显示中文名称，替换原生 title；复用现有 radix-ui，不增加依赖。
- 左侧三个分类固定为“浏览器扩展”“桌面应用”“协同功能”；默认展示“浏览器扩展”，切换分类后右侧展示相应内容。
- 浏览器扩展首个模块为 **Tabs**：在新标签页集中访问常用网站，整理分组标签。
- 桌面应用首个模块为 **Photos**：按月份浏览 iPhone 照片与视频，批量下载到本地。
- 协同功能保留分类入口；目前显示“暂无协同功能”，不虚构模块或承诺上线时间。
- 右侧每个模块只包含标题和一句介绍；同一分类未来有多个模块时按相同结构纵向排列，本次仅交付 Tabs、Photos。
- 沿用 Changelog 的共享布局、字体和留白规范；窄屏保持三个分类可访问、正文完整可读。
- 内容使用本地静态文案，不新增依赖或外部数据请求。

## 验收标准

- 任意官网页面均能从“更新日志”旁的“产品介绍”入口进入功能介绍页，页面地址可直接访问。
- 三页共用 Layout，Header／Footer 的尺寸、边框、横向位置和正文预留相同；长短页面切换不因滚动条造成横向偏移。
- 产品介绍与更新日志的阅读宽度、标题和基础排版一致；分别保留分类与时间轴结构。
- 两个导航入口分别为 BookOpen 与 FileClock，悬停或聚焦显示“产品介绍”“更新日志”，无重复原生 title 提示。
- 默认选中“浏览器扩展”，右侧仅显示 Tabs 标题及批准的一句话介绍。
- 切换“桌面应用”后，右侧仅显示 Photos 标题及批准的一句话介绍。
- 切换“协同功能”后显示“暂无协同功能”，没有虚构模块或上线承诺。
- 页面使用纯文字布局，没有截图、展示卡片、额外能力标签或详细操作说明。
- 页面风格与 Changelog 一致；用户在 Chrome 或 Edge 检查桌面与窄屏时，分类入口和正文无截断。
- 必要自动化验证通过；浏览器视觉与交互由用户验收，不把自动化结果写为用户验收通过。

## 用户验收步骤

1. 在仓库根运行 `pnpm web:dev`，用 Chrome 或 Edge 打开命令输出的本地地址。
2. 点击更新日志旁的书本图标“产品介绍”，确认进入 `/features/`；默认左侧选择浏览器扩展，右侧显示 Tabs 标题和一句介绍。
3. 点击桌面应用，确认右侧变为 Photos 标题和一句介绍；点击协同功能，确认只显示“暂无协同功能”。
4. 返回浏览器扩展，确认 Tabs 恢复；直接访问并刷新 `/features/`，确认页面正常，默认展示 Tabs。
5. 缩窄窗口，确认三个分类与正文完整可读；检查布局与 Changelog 风格一致，无截图、卡片或详细说明。
6. 分别访问首页和更新日志，确认新增入口可用、原导航与首页内容正常。
7. 在同一窗口依次切换首页、产品介绍、更新日志，确认 Header 边框、Logo、导航和 Footer 位置一致；将系统滚动条设为始终显示，再比较长短页面切换是否有横向偏移。
8. 对比产品介绍与更新日志的标题、阅读宽度、顶部间距及正文样式；仅分类和时间轴内容不同。
9. 悬停书本／带时钟的文件图标，确认提示为“产品介绍”“更新日志”；用 Tab 聚焦入口，确认提示可见，Escape 可关闭，没有额外原生 title 提示。
