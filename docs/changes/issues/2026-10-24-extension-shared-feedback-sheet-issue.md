## 背景与目标

共用 Sonner 已有等级图标和右下角位置，但业务仍直接导入提示 API，TG 仍显示文件名描述。Download 与 Settings 分别维护 560px 宽度。本次复用现有 shadcn 通用组件，统一提示入口及规则，把两个抽屉宽度集中到 Sheet。

## 范围

- shared/ui/sonner.tsx 统一导出 Toaster 与现有 Sonner toast API；复用 Lucide 成功、信息、警告、错误图标及现有主题，无新增提示封装或队列。
- 提示在各自页面右下角显示图标加提示语，不带第二层描述或品牌专属配色；TG 完成仅显示“下载完成”，文件名仍在下载记录中。
- Download 文件夹未接入提示使用 info，清空失败使用 error；TG 使用 success。warning 保留官方类型能力，不新增业务触发。
- 规范要求后续 X 接入同一组件及规则，但本次不实现 X 下载或提示事件。TG 完成条件、失败和取消不弹 Toast 的边界保持不变。
- 共用 Sheet 的右侧默认宽度为 420px，最大不超过视口；Download/Settings 删除各自宽度覆盖，其余方向保持原行为。

## 排除项

- 不修改主题配色、官方交互、Sheet 遮罩和焦点规则，不引入视觉或交互测试。

## 用户验收步骤

1. Chrome/Edge 重新加载根 dist/build/chrome-mv3，刷新 Telegram Web K 并打开新标签页。
2. 分别打开 Download、Settings，检查两者宽度一致且变窄，调整到窄窗口时不超出视口；原设置项、记录、筛选和清空流程应正常。
3. Telegram 成功保存媒体后，右下角只显示成功图标及“下载完成”，无文件名副标题；取消不提示，Download 仍显示真实文件名。
4. Download 点击文件夹，检查右下角显示信息图标与未接入提示。检查明暗主题一致；错误及警告图标沿用公共组件已有映射，不为验收新增业务触发。

## 验收标准

- TG 保存成功后在 Telegram 页右下角显示成功图标及“下载完成”，没有文件名副标题；取消、失败不新增 Toast。
- Download 文件夹未接入显示信息图标，清空失败显示错误图标；四种等级沿用 shadcn Sonner 与 Lucide，后续 X 可直接复用。
- Download 与 Settings 同为 420px，窄屏不超过视口，宽度只在共用 Sheet 维护；记录和设置功能不变。
- 实际视觉、位置和交互由用户在 Chrome/Edge 验收，自动化结果不等于用户验收。
