- 用户批准：GitHub 旁增加 Lucide History 图标入口；独立时间线页面，无版本号与副标题，黑底白字圆角平台标签独立一行，正文统一无序列表。首批沿用三条日志，日期使用对应交付 Git 提交的北京时间；用户进一步批准按年份分组，桌面最左侧年份每组一次、日期只显示月日，手机年份置于组上方；年份可点击返回该年第一条，提供悬停、按下和键盘焦点反馈。用户明确允许上一项已验收结项文档留到后面一起提交，并要求继续本项，作为先提交上一项才能开新项规则的本次例外；未批准本轮 Git Commit 或推送

## 背景

官网目前只有产品首页，需要从首个正式 Release 开始记录用户可观察的产品进展，使用已确认的时间线排版。

## 目标

从首页图标进入独立 Changelog 页面，按时间倒序阅读三条真实更新；页面可以在 GitHub Pages 直接访问和刷新。

## 范围

- 页头 GitHub 旁增加 History 图标，以现有 shadcn Button 承载链接；Exts 品牌链接返回首页。
- 独立 /changelog/ 页面，复用页头、页脚，按年份分组：桌面最左侧年份每组一次，日期仅显示月日，手机年份在组上方；使用节点和连线形成时间线。
- 标题不显示版本号；无副标题，标签单独一行，仅使用 Website、Chrome、macOS 三种平台名称，统一黑底白字小圆角 shadcn Badge；内容采用无序列表。
- 独立模块维护静态日志数据与时间线，首批包含官网上线、Latest 下载入口改进和首版扩展发布。日期以相关代码交付 Git 提交的北京时间记录，同日按实际时间倒序。
- 使用现有 Vite 多页面静态构建，输出 changelog/index.html，不引入路由库或其他依赖；保持根版本与既有构建、手动部署方式。
- 同步官网说明、Issue、Commit 记录与工作台；上一项结项记录保留等待后续统一提交安排。

## 排除项

- 不补写首版之前的个人经历，不自动读取 GitHub API，不把内部 Commit 全部作为日志。
- 不增加版本号、搜索、筛选、分页、动画或其他页面功能。
- 不修改下载行为、产品版本、依赖版本或品牌图标，不执行浏览器视觉与交互验收，不自动提交、推送或部署。
