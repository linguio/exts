## 背景

Photos 既有功能由用户确认正常，本项以此为基线。现有 `pnpm desk:dev` 已支持构建并直接打开开发 `.app`；`pnpm release` 已支持完整构建并生成 `dist/release/exts-chrome.zip`、`dist/release/exts-mac.dmg`，不另建重复打包命令。

当前 `Exts Publish` 的 Website 选项部署官网，Chrome 选项只生成扩展草稿 Release，Desktop 选项仅提示未接入。用户现要求每次产品 Release 同时包含两包，因此旧的单端发布选项、提示和发布说明需要同步调整。

## 目标

先确认本地开发 `.app` 和正式 DMG 构建可用，再通过手动 Actions 生成包含两包的同一草稿 Release；用户下载 DMG 安装后使用现有 Photos。

- 保持 macOS 27 最低版本，不做旧系统兼容；保留开发与正式身份、缓存和配置隔离及已有用户文件。默认下载目录按用户新批准规则共用，旧文件不迁移。
- 本地调试继续使用 `pnpm desk:dev`，无需生成 DMG、安装或配置分发证书；正式分发复用 `pnpm release`，保留固定附件名 `exts-chrome.zip`、`exts-mac.dmg`。
- 处理构建、启动、打包的必要阻塞及用户确认的 Photos 验收问题：按可见性加载缩略图、离屏移除排队任务、保持已加载图片与稳定布局；目录完成后发布按月份和月内时间倒序的数据，只在目录变化时重新分组；请求最长边 512 像素设备缩略图并与旧缓存区分。不扩展其他 Photos 功能。
- 将 `Exts Publish` 的 Chrome、Desktop 选项合并为 Release，保留 Website；调整运行标题、任务名称、输入描述、步骤、摘要、错误提示与草稿安装说明，使其符合双包行为。

## 验收标准与步骤

1. 本地运行 `pnpm desk:dev` 后产物为 `dist/dev/exts-dev.app`，直接启动调试，无需先安装 DMG；用户确认现有 Photos 可用。
2. 本地运行 `pnpm release` 后同时存在 `dist/release/exts-chrome.zip`、`dist/release/exts-mac.dmg`，包内版本与根版本一致；DMG 校验成功，包含正式 `exts.app` 与 Applications 安装入口。
3. 用户挂载 DMG，将正式应用拖入 Applications 并启动，确认现有 Photos 正常；代理不以构建成功代替实际安装或设备验收。
4. 检查 workflow 与现行说明：Website 仍只部署官网；Release 明确生成两包，不再保留 Desktop 未接入或仅含扩展的失效提示。扩展无功能变化时仍生成同版本 ZIP。
5. 本地验收并提交、推送后，由用户手动选择 Release 运行 Actions；成功时同一草稿包含两个固定名附件。用户下载 DMG 安装验收后自行决定公开 Release；草稿附件不等同于公开下载地址已可用。
6. 构建或包校验失败不得创建成功的 Release；版本冲突明确失败，不覆盖已有附件、不删除或移动旧 Tag。上传等外部操作中途失败必须真实报错，不把不完整草稿报告为成功。
7. Photos 首屏只加载当前可见照片的缩略图；向下滚动才请求新进入屏幕的照片，已滚走的排队任务不再继续启动。最多四个已发出的设备请求允许完成，结果可缓存，不预先下载原图。滚回已加载照片时使用缓存，缩略图出现前后格子尺寸不变。
8. 月份从新到旧，月内优先按拍摄／创建时间倒序，缺少时使用修改时间，无日期的归到末尾；同时间用稳定标识排序。设备较大预览与旧缓存分开，清晰度、滚动闪动和真机请求行为由用户实测验收，不新增视觉或交互自动化测试。
9. 下载完成弹出原生 alert：全部成功显示实际成功数量，部分成功显示成功／失败数量并列出失败原因，全部失败明确提示失败。附属文件错误须独立提醒，不能误报完整成功；存在成功文件时提供“在 Finder 中查看”，打开实际下载目录。大量错误只展示前五条并注明剩余条数。
10. 开发与正式均写入 `~/Downloads/Exts Downloads/Photos/`，同名文件继续不覆盖；历史下载目录和文件不移动或删除，缓存和配置身份保持原有隔离。
