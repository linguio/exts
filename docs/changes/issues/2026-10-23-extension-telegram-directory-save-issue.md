## 背景与目标

原 TG 下载每次调用系统另存为。此次目标是快速保存到记住的文件夹，并能随时更换位置。此前限定 Exts/Telegram 的方案已被用户取消；用户实际选整个 Downloads 曾被浏览器“含有系统文件”提示阻止，这是浏览器授权限制，不应增加业务名称限制。

## 范围与最终设计

- 菜单只有“下载资源”和“选择文件夹”，无常驻提示。必要错误时显示恢复说明；完成后沿用“下载完成”和实际文件名的 Toast。
- 下载资源：未配置时在点击栈内弹目录选择器，选好并持久化后立即保存本次媒体；已有选择时直接写入所选目录。取消首次选择不取流、不保存。
- 选择文件夹：仅记住或更换后续保存位置，不立即下载；取消或持久化失败保留原选择。
- 任意浏览器允许的文件夹均可，无名称限制，不自动创建固定子目录。旧版句柄继续表示当前保存目录，不迁移、删除或整理历史文件。
- Telegram 页面 MAIN world 继续取流与写入；句柄保存在同来源 IndexedDB，启动读取至内存，首次读取完成前暂禁用操作。点击栈内请求权限，不先等待存储再打开选择器。
- 同名文件/目录递增后缀，Web Locks 保护同来源的名称检查与文件占位，实际下载流并行。浏览器拒绝某些受保护目录时，用户另选普通子目录；不绕过限制。
- 目录 API 或锁不可用时，下载资源降级为原系统另存为，保留 picker id、桌面建议位置和基础文件名，不保留独立另存为菜单项。
- 开关、媒体识别、基础文件名、Range 取流及成功关闭文件后才提示完成的规则保持；直接相关的功能说明和现行边界同步更新。
- 已在本 Issue 首次实施前提醒用户可切换较低成本模型。
