## 背景与目标

目前 `modules/tg-download` 负责 Telegram 下载与网页菜单，`modules/downloads` 负责共享下载记录。希望统一归入 `modules/media-dl`，内部按来源分为 `tg-dl`、`x-dl`，共用记录数据及订阅接口。

## 当前代码事实

- Newtab 下载列表在 `modules/newtab/views/downloads`，Dock 提供抽屉外壳。
- Telegram 专属设置视图目前在 `modules/tg-download/views/settings`，由 Newtab Settings 引用；需要按新的数据／视图边界调整。
- Telegram 网页下载按钮和菜单在 `modules/tg-download/components/download-menu`。
- `modules/downloads` 提供记录结构、存储、后台消息与读取／清空／订阅接口。
- X 下载仍在 `archive/apps/extensions/x-download`。归档实现通过 Native Messaging 交给桌面 Helper；成功响应表示任务已接收，不代表文件已下载完成。此事实不等于当前 Exts Desktop 已具备对应协议。

## 已确认方向与拟定范围

- 顶层模块采用 `media-dl`，来源子模块采用 `tg-dl`、`x-dl`。
- media-dl 中只保留平台网页上的下载按钮／菜单等自身下载操作视图；下载列表继续留在 Newtab。
- 设置界面也由展示页面持有，订阅业务模块的数据，通过接口修改；不从下载模块向外挂载设置视图。
- TG、X 最终写入同一份下载记录，Newtab 订阅该数据源；不让列表分别拼接两份独立状态。
- 可以提取真正共用的下载方法，但公共方法的职责尚未确认，不先强行统一 TG 网页保存与 X 桌面执行。
- X 的桌面通知／任务同步归来源实现处理；Newtab 列表通过统一数据了解结果。

## 待讨论，不能视为已批准

1. 首个工作项是否只合并现有 TG 与记录模块、调整设置视图归属，X 接入另建主 Issue；不为占位预建空的 x-dl。

6. 跨 TG／X 写入继续由扩展后台统一处理的具体接口，以及 X 同步记录的稳定标识与去重方式。
7. 保持现有设置数据源与存储键，还是进行迁移；目录重组不自动批准存储迁移或权限变更。
