# 统一 Exts 登录、授权与退出窗口

## 元信息

- 工作项：2026-11-04-extension-auth-window-unification
- 状态：已完成（部分交付）
- 当前阶段：用户明确要求本地提交当前页面改动；固定浏览器外框和退出失败定位未完成，后续另行处理。
- 批准依据：用户要求 Google/GitHub 登录、授权、退出的自有页面与窗口样式、大小、出现位置统一，并指定先写 Issue。
- 任务规模：中型；官网 UI 与插件认证窗口有依赖，涉及浏览器窗口控制及回跳，不新增业务数据或认证提供方。

## 背景与目标

现有官网登录、授权与退出页使用大面积空白布局，认证窗口由 `chrome.identity.launchWebAuthFlow` 自行决定尺寸和位置。用户希望三个自有页面采用统一的 shadcn 风格、紧凑尺寸与固定出现规则；Google 与 GitHub 共用同一套体验，只随提供方变化必要文案。

## 当前范围

- 以已选「紧凑工具窗」demo 为方向，统一 `/auth/sign-in/`、`/auth/consent/`、`/auth/sign-out/` 的容器、品牌区、标题、说明、操作区、加载与失败状态；复用现有主题 Token 与适用的 shadcn 官方组件。
- 登录、授权、退出在同一种浏览器窗口中呈现，目标为相同外框尺寸与相同居中规则；默认设计基准暂定为约 `520 × 460` CSS 像素、相对当前浏览器窗口居中，最终值按内容与浏览器 API 实测确定并征求用户确认。窄视口须可完整操作，授权内容过长时使用官方 Scroll Area 或其既有组合，不裁切权限与安全信息。
- 先验证 Chrome/Edge 对认证窗口尺寸、位置、关闭和回跳的实际控制能力。当前 `launchWebAuthFlow` 没有宽高/坐标参数；若必须改用自管窗口，先记录权限、回跳、取消和安全差异，经用户确认后实施，不把 CSS 居中冒充窗口居中。
- 保留显示真实客户端、回调目标、scope/resource、风险提示及允许/拒绝；展示文字可重排，但不隐藏实际请求信息。
- 登录提供方仍为 GitHub/Google，第三方账号选择与第三方授权页由对应平台控制；统一范围仅覆盖 Exts 自有页面与可控浏览器窗口。
- 退出失败提示必须清楚，当前用户报告的“退出未完成，请重试”真实原因需先定位；窗口重设不得掩盖失败或伪装成功。

## 排除项

不重绘 Exts 品牌图标，不更改 Neon OAuth 配置、用户账号关联、令牌协议、权限范围、业务表、官网首页或第三方 Google/GitHub 页面；不自动提交、推送或部署。

## 验收标准

- Google 与 GitHub 的 Exts 登录页视觉、外框尺寸和出现规则一致；授权与退出页也使用同一窗口规范，内容完整可读。
- 不同页面、加载/失败状态及长 scope/resource 不改变外框尺寸、不遮挡安全信息；窗口关闭、拒绝和退出失败可重试。
- 用户在 Chrome/Edge 实际观察窗口位置与尺寸符合最终确认规则；第三方页面按提供方原生流程显示，不宣称可定制。
- 认证与注销安全边界仍有效，真实退出失败被定位和处理，不把自动化或设计预览当作浏览器验收。
