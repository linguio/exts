# 划分 Newtab 三区布局并添加右侧卡片

## 背景

Newtab 当前书签区域使用换行排列，Dock 固定在页面底部。用户希望右侧有独立整列区域，为后续打卡功能提供位置；先完成三区布局和右侧第一张卡片，不实现打卡业务。

## 目标

将页面内部划分为左侧书签、右侧模块区域和底部 Dock。左右内容只在各自区域内滚动，不覆盖 Dock；右侧先展示一张与现有文件夹尺寸有关联的横向占位卡片。

## 范围

- 保持现有页面外圈 24px 边距，不额外叠加外圈留白。
- 上方左右分栏，底部整行给 Dock 留出空间；沿用 Dock 本身的内容宽度、居中位置和横向展开能力，不将 Dock 背景拉伸至整行。
- Dock 最大宽度受底部可用区域约束，内容撑满后仅在 Dock 内部横向滚动；隐藏滚动条且不预留滚动条槽位，不让 Dock 超出页面可用范围，也不使页面整体横向滚动。此行为仅在实际溢出时生效，不为验证添加生产入口。
- 左右区域边界之间保持 24px，上方区域底边与 Dock 外框顶边之间保持 24px。
- 右侧列宽固定，左侧占剩余宽度；窗口变窄时左侧书签换行，右侧不移到左侧下方。
- 左右区域内容溢出后只能在各自区域内部滚动；通常为纵向滚动，若内容横向溢出也必须限制在所属区域内，不侵入另一区域。隐藏滚动条且不预留滚动条槽位，保留滚轮及触控板滚动能力；页面整体不随内容滚动，左右内容包括展开后的文件夹均不得侵入或遮挡 Dock 区域。
- 右侧第一张卡片顶部与左侧第一排文件夹外框顶部对齐，高度与文件夹预览外框一致，不含外框下方名称及其间距。
- 卡片外框宽度为两个文件夹外框宽度加一个现有文件夹间距：`2 × 文件夹外框宽度 + 24px`。按当前默认尺寸约为 380px 宽、178px 高；以现有尺寸关系为准，包含卡片自身边框及内边距，不额外扩大右侧列宽。
- 左侧保留固定尺寸书签与文件夹，不拉伸填满；每行尾部允许剩余空白，因此最后一个文件夹到右侧卡片的实际可见距离可以大于 24px。
- 本期卡片仅提供占位外框，复用现有主题、圆角与材质，不添加未经确认的标题、打卡按钮或统计内容。卡片必须有独立组件及文件夹，不能直接内联在页面入口或仅以一个零散小组件承载未来全部职责；具体目录方案见下节。

## views 目录与职责方案（已批准）

```text
src/modules/newtab/views/
├─ bookmarks/
│  └─ bookmark-grid.tsx
├─ dock/
│  ├─ bookmark-dock.tsx
│  ├─ dock-tool-menu.tsx
│  └─ dock-settings.tsx
├─ cards/
│  ├─ index.tsx
│  └─ check-in/
│     └─ index.tsx
└─ settings/
   └─ general-settings.tsx
```

- `src/app/NewtabApp.tsx`：页面级三区布局，组合书签、右侧卡片区域和 Dock，持有区域间距与可用空间约束，不承担具体卡片内容或业务。
- `views/bookmarks/`：仅组织左侧书签列表；既有书签卡片和文件夹组件继续位于 `newtab/components/`。
- `views/dock/`：从 `views/bookmarks/` 移入现有 Dock、工具菜单及设置入口文件，调整引用，不改其业务行为；设置入口仍组合 `views/settings/` 及独立功能设置。
- `views/cards/index.tsx`：独立的右侧卡片区域组件，负责当前卡片组合和纵向排列，不承载单张卡片的业务；列宽及三区布局仍由页面负责，滚动容器按区域边界设置。
- `views/cards/check-in/`：第一张打卡卡片的独立功能目录，`index.tsx` 为卡片入口；本期只展示已确认尺寸的外框。后续实际需要子组件、状态、数据处理或增删改时，在此目录内按职责拆分文件，不把所有内容堆进入口，也不预建空目录或空逻辑文件。
- 后续其他卡片各自使用 `views/cards/<卡片名>/` 目录，由右侧区域组合；本期不增加卡片注册系统、动态类型分发、持久化或通用增删改框架。
- 当前仍属于 Newtab 内部功能目录，不新增 `src/modules/check-in/`。若后续打卡需要后台任务、其他页面入口或独立共享数据能力，再在相应 Issue 中确定是否提升为独立 module。

## 实际完成与验证

- `NewtabApp.tsx` 与 `newtab.css` 使用视口高度网格划分三区，上方两区各自滚动；Dock 行独立保留高度，内部内容撑满后横向滚动；滚动条统一隐藏。
- 文件夹外框宽度与首张卡片高度引用同一主题尺寸基准，右侧列宽由两个基准加 24px 计算；没有新增打卡数据或操作。
- Dock 三个文件移入 `views/dock/`，原有工具菜单与 Settings 行为保留；右侧区域和首张卡片分别位于 `views/cards/index.tsx` 与 `views/cards/check-in/index.tsx`。
- 首卡使用现有固定官方版本的 Card 根组件，组件来源及必要主题差异记录在 `docs/web-ui-sources.md`，未新增依赖。
- `pnpm --filter @exts/extension test --maxWorkers=1 --no-file-parallelism`：10 个测试文件、45 项测试通过；初次默认测试因沙箱拒绝子进程 `spawn EPERM` 未执行断言并已停止，改为允许子进程的环境串行重试一次后通过。
- `pnpm --filter @exts/extension typecheck` 与 `pnpm ext:build`：通过。Manifest 可解析，版本保持 1.3.0，Newtab 入口及 HTML 引用的构建脚本、样式存在；diff 空白检查通过。
- 构建保留既有 `theme-init.js` 非 module 提示，不影响成功生成；未执行浏览器视觉、布局、滚动、菜单或设置交互验收，未运行开发服务器、更新稳定开发目录或执行 Git Commit。

## 本阶段用户验收步骤

1. 在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，加载或重新加载 `D:\GitHub\exts\dist\build\chrome-mv3`。本次为生产构建，原 dev 稳定目录未更新。
2. 打开 Newtab，应看到左侧原有书签、右侧一张空卡片和底部居中 Dock。检查外圈留白不变，左右区域间及上方区域与 Dock 间均为 24px；右侧空卡片与文件夹预览外框顶部对齐、等高，宽度相当于两个文件夹加间距。
3. 缩小窗口宽度，检查左侧书签换行且右侧仍在右边；左侧行尾允许留白。降低窗口高度，分别在左右区域滚动，溢出内容只能在所属区域内移动，不能遮挡 Dock，不出现滚动条；右侧仅一张空卡片，可通过降低高度触发溢出，不添加额外生产卡片。
4. 缩小可用宽度使 Dock 内容撑满，使用触控板横向手势或 Shift+滚轮检查内部横向滚动，末端 Settings 入口仍可到达，不显示滚动条；若设备无法触发横向输入或未触发溢出，记录该项尚未验证。
5. 检查普通书签打开、EDU 解除模糊、Components/DevTools 菜单、Settings 及主题切换与原有行为一致。未通过的布局或交互继续在当前 Issue 修正。

## 验收标准

- 现有外圈留白不变，左右区域之间及上方区域与 Dock 之间均为 24px，不重复计算外圈边距。
- Dock 在底部独占整行可用空间，自身保持现有外观与展开能力，不被左右内容遮盖。
- Dock 内容未撑满时保持内容宽度及居中；撑满底部可用区域后在内部横向滚动，滚动条不可见，Dock 本身和页面不横向溢出。
- 右侧位置与列宽稳定；调整窗口宽度时，左侧自动换行，行尾空白不影响右侧定位。
- 右侧首张卡片与文件夹预览外框顶部对齐、等高，宽度等于两个外框加一段 24px 间距。
- 左右各自内容溢出时只在所在区域内部滚动，滚动条不可见，整体页面与 Dock 不跟随滚动；文件夹展开后的内容同样不能遮挡 Dock。
- 原有书签导航、文件夹与 Dock 功能保持可用；不出现打卡业务、接口接入或数据权限变更。
- `views/bookmarks` 不再混放 Dock 文件，右侧区域与第一张卡片分别有独立组件入口，第一张卡片有自己的目录；页面入口不内联具体卡片实现。
- 自动化结果如实记录，浏览器视觉与交互由用户验收，不将测试通过写成用户已验收。
