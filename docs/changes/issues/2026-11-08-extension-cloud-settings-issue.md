# 将扩展设置统一保存到账号

## 元信息

- 工作项：2026-11-08-extension-cloud-settings
- 状态：已完成
- 当前阶段：表、接口和扩展接入已完成；当前 API 数据库迁移已应用，用户已确认验收通过并批准本地提交
- 已批准范围依据：用户最终选择设置独立于 user info、线上保存并保留 `chrome.storage.local` 账号副本；每次点击以接口成功结果为准并提示；默认值为 `system`、`false`、`false`，首次成功修改才建行；本地 `settings` 保持业务字段结构，加入 `userId`，不保留 `version`，不考虑旧数据。
- 规模：架构任务，涉及数据库结构、业务 API、扩展设置数据源和后台触发行为。

## 背景与目标

当前三个设置共用 `chrome.storage.local` 的 `settings` 对象，Theme 另有页面 `localStorage` 首屏缓存；登录和退出会清理这些数据。改为账号配置后，同一账号重新登录可读取服务端保存的选择，当前账号的本地副本支持即时显示及离线时的既有行为，切换账号不残留上一账号的设置。

## 范围与排除项

- 新增每用户一行的 `public.user_settings` 表：`user_id` 为主键并关联认证用户，字段为 `theme`、`media_download_enabled`、`history_cleaner_enabled`、`created_at`、`updated_at`；删除用户时清理对应设置。默认值分别为 `system`、`false`、`false`。数据库结构使用新迁移管理，不加入 `version`。`created_at` 由后续迁移补充；既有记录以 `updated_at` 近似回填创建时间。
- 新增 `POST /api/settings/preferences` 读取本人完整设置，以及 `POST /api/settings/preferences/update` 按本次点击的单个字段更新并返回完整设置。没有记录时读取默认值、不写库；首次成功更新时创建记录。请求身份来自已验证令牌，不接受客户端 `userId`；拒绝未知字段、无效值、`null` 与空更新。响应沿用 `{ "data": ... }` 和现有 HTTP 错误格式，业务响应不缓存。
- 扩展使用现有后台认证与共用业务请求层调用设置接口；未登录时可查看和修改本机离线设置，初始值为 `system`、`false`、`false`，修改才写入本机。登录后只使用当前账号云端设置，云端无记录使用默认值，不导入离线设置；多个调用方复用读取结果。成功保存后才更新控件、Theme 与本地副本，并提示“已保存”；失败保留原值并提示错误。同一控件保存期间不能再次发起修改，迟到响应不能污染切换后的账号状态；意外 `401` 按共用认证错误处理。
- 本地继续使用 `chrome.storage.local` 的 `settings` 键，保留 `theme`、`mediaDownload.enabled`、`historyCleaner.enabled` 的结构；登录副本增加 `userId`，未登录离线设置不带账号。退出或换账号时按现有会话重置流程全部清除，回到内置默认值。已有账号副本可供首屏、Telegram 和关窗清理即时使用，随后用线上值刷新；账号登录但离线时允许使用已确认属于当前账号的副本，不能离线修改云端设置。Theme 现有同步首屏缓存只用于即时显示，退出或换账号时清除。
- Clear History 开启前仍须在点击手势内请求本机 `browsingData` 权限；拒绝授权时不保存开启状态。实际清理同时要求当前有效设置的开关开启和浏览器权限有效。浏览器启动及最后一个窗口关闭的后台触发不等待设置接口；登录时启动后另行尝试线上刷新，线上不可达时沿用同账号副本。
- Telegram 页面下载入口及主题使用当前有效设置，设置变化继续通过现有订阅同步到已打开页面。旧数据不迁移，未登录本机设置不作为账号云端设置。
- 退出或重新登录时不打开或等待 Telegram Web 页面。扩展先清理自身数据并留下 Telegram 专用目录待清理标记；已打开的页面或下次打开的页面先中止扩展下载、清理目录句柄，再启用下载入口。Telegram 页面失败不阻塞账号操作，不清理 Telegram 网站自身数据。
- 排除项：浏览器管理的权限、历史记录本身及账号删除流程；不改 Activity 数据。不新增离线云端写入队列、定时轮询或自建 user info 接口；不在本项推送或部署。

## 同步与行为边界

- 线上是最终设置来源；本地副本只在账号相符时用于快速读取和离线沿用。其他设备修改后的值在本机下一次成功读取线上前可能暂时不同。浏览器完全退出时，异步历史删除本身仍可能来不及完成；现有启动清理保留作为兜底，不承诺浏览器退出瞬间必定删除。
- 没有同账号副本且线上不可达时，不把默认值当作已保存的账号设置；History Cleaner 不执行未知账号开关，Telegram 下载入口不启用。未登录时使用本机设置或内置默认值，Theme 默认跟随系统。浏览器管理的 `browsingData` 权限不由数据库或副本替代。

## 验收标准

- 未登录打开 Settings 直接查看和修改本机设置，设置页不包含账号判断、登录提示、登录入口或登录后刷新操作；初次为默认值。账号流程登录后读取本人云端配置，无行时使用默认值，不带入本机值。同一账号重新登录恢复已保存值，换账号不显示上一账号值；退出清空后回到未登录默认值。
- 未登录三项设置修改只写本机；已登录时每次有效修改调用接口。成功后控件或 Theme 才变更并提示成功，失败不变更并提示错误。连续操作、退出期间迟到响应不能覆盖当前账号状态。
- Clear History 在当前有效设置显示开启且本机权限存在时执行；未授权开启有清晰提示，不错误显示成功。关闭最后一个窗口时不等待线上接口；已登录时启动后尝试从线上刷新。账号副本缺失或账号不匹配时不能执行未知开关。
- Telegram 下载入口及主题使用当前有效设置；登录后线上不可达时沿用已确认账号副本，缺失时不启用未知下载开关。退出后目录句柄在页面下次启用下载前清理，浏览器权限不清除。
- 真实 Chrome/Edge 中由用户验收设置面板、主题、权限和浏览器事件；自动化检查不替代视觉或交互验收。
