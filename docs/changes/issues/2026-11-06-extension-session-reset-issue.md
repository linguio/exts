# 统一登录初始化与退出重置

## 背景与目标

仅重建 React 组件无法清除持久化数据。统一处理登录前本地重置、退出清理及账号初始化，避免每个业务模块分别维护清理函数，让下一次登录从扩展默认状态开始。

## 范围与排除项

- 清点扩展实际使用的 IndexedDB、chrome.storage、Local/Session Storage、应用缓存及运行中任务。核实媒体下载等内容脚本是否将扩展自有数据保存在网站来源，设计仅处理自有数据的方法，不整站清空网站存储。
- 登录前先统一重置旧本地状态，再开始认证；保留新登录产生的凭据。页面恢复现有有效登录不等同重新登录，不因打开 Newtab 就清除认证。
- 退出流程停止旧会话请求与写入，完成应用认证退出并清除扩展自有凭据、设置及记录；清理完成后统一重建/重载打开的扩展页面和后台相关运行状态，避免隐藏 Home/Studio 或其他 Newtab 保留旧状态。
- 复用现有账号广播及前项请求能力，处理迟到响应和清理后重新写入。采用单一重置入口，不做清理注册框架、逐模块退出管理器或复杂状态架构。
- 清理失败不得报告恢复成功；凭据撤销失败、部分清理失败、其他页面占用 IndexedDB 等情况的顺序及恢复行为需详细设计确认。
- 不再保留扩展自有设置和下载记录的旧退出策略；所有实际持久化位置以核查结果列明。可写存储与浏览器管理的数据明确区分，不宣称等同真正卸载。
- 排除项：删除云端 Activity、已下载文件、浏览器书签/历史或第三方网站账号数据；不重置浏览器管理的权限，不扩展 Activity 字段和 CRUD。清理自有数据不等同注销第三方账号。本轮不执行清理、提交或部署。

## 验收标准

- 登录前恢复默认本地业务状态，新产生的认证凭据仍有效；恢复已有登录不误清凭据。
- 退出完成后扩展自有持久化数据已清理，所有扩展页面展示默认未登录状态，不靠逐模块手动清理。
- 旧请求/任务不能在清理后恢复上一账号数据；清理不完整时不提示成功。
- 云端记录、真实文件及第三方网站数据不受影响；浏览器权限和真正卸载的差异如实说明。
- 实际清理需用户在专用 Chrome/Edge 配置文件验收，代理不清除日常浏览器数据。
