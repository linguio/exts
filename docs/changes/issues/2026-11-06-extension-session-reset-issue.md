# 统一登录初始化与退出重置

## 元信息

- 工作项：2026-11-06-extension-session-reset
- 状态：已完成
- 当前阶段：代码与文档分别本地提交完结；最终代码的真实浏览器复验未单独记录
- 已批准范围依据：用户要求退出后重新登录视作全新账号会话，扩展内不残留上一个账号的本地信息；下载记录、目录句柄及在途下载均纳入。用户批准按使用情况复用数据库连接，连接池参数调整作为独立后续工作项。
- 规模：架构任务，涉及凭据、跨页面状态及持久化数据清理。

## 背景与目标

仅重建 React 组件无法清除持久化数据。统一处理登录前本地重置、退出清理及账号初始化，避免每个业务模块分别维护清理函数，让下一次登录从扩展默认状态开始。

## 范围与排除项

- 清点扩展实际使用的 IndexedDB、chrome.storage、Local/Session Storage、应用缓存及运行中任务。Telegram 目录句柄位于网站来源的专用 IndexedDB，必须定向清除该库，不整站清空网站存储。
- 登录前先统一重置旧本地状态，再开始认证；保留新登录产生的凭据。页面恢复现有有效登录不等同重新登录，不因打开 Newtab 就清除认证。
- 退出流程停止旧会话请求与写入及在途下载，完成应用认证退出并清除扩展自有凭据、设置、下载记录及目录句柄；清理完成后统一同步打开的扩展页面和后台运行状态，避免隐藏 Home/Studio 或其他 Newtab 保留旧数据，不整页刷新或整体重建组件树。同一账号再次登录也必须使用全新会话，不能复用旧内存数据。
- 复用现有账号广播及前项请求能力，处理迟到响应和清理后重新写入。采用单一重置入口，不做清理注册框架、逐模块退出管理器或复杂状态架构。
- 清理失败不得报告恢复成功；凭据撤销失败、部分清理失败、其他页面占用 IndexedDB 等情况的顺序及恢复行为需详细设计确认。
- 不再保留扩展自有设置和下载记录的旧退出策略；所有实际持久化位置以核查结果列明。可写存储与浏览器管理的数据明确区分，不宣称等同真正卸载。
- 排除项：删除云端 Activity、已下载到电脑的文件、浏览器书签/历史或第三方网站账号数据；不重置浏览器管理的权限，不扩展 Activity 字段和 CRUD。清理自有数据不等同注销第三方账号。数据库连接池空闲时间优化独立处理；本项不提交或部署。

## 验收标准

- 登录前恢复默认本地业务状态，新产生的认证凭据仍有效；恢复已有登录不误清凭据。
- 退出完成后扩展自有持久化数据（含 Telegram 专用目录句柄）已清理，所有扩展页面展示默认未登录状态，不靠逐模块手动清理。
- 旧请求/下载任务不能在清理后恢复上一账号数据；清理不完整时不提示成功。同一账号重新登录也不沿用旧会话数据。
- 云端记录、真实文件及第三方网站数据不受影响；浏览器权限和真正卸载的差异如实说明。
- 实际清理需用户在专用 Chrome/Edge 配置文件验收，代理不清除日常浏览器数据。
