## 背景与目标

Newtab 已有右侧独立卡片外框，本次在现有尺寸内展示本地 JLPT 学习日历。数据与组件分离，不接入 GitHub，不增加计时、编辑或同步能力。

## 范围

- 保留现有卡片 380×178px 的默认外框、16px 内边距及三区布局。
- 首行左侧为 `Daily check-in`，右侧使用 Settings 同款官方 ToggleGroup，只有 `JLPT` 一个固定选中项；首行高 32px，与日历间隔 16px。
- 日历为 24 列、7 行，每格 12px、间距 2px，共 334×96px，水平居中。每列一周，首行为周日，末行为周六；最右列为本地当前周，向左显示前 23 周。
- 本地 JSON 放在 `src/modules/newtab/views/cards/check-in/data/jlpt.json`，日期键为 `YYYY-MM-DD`，值为当天累计整数分钟数。本次生成 2026-09-23 至 2026-10-22 共 30 天的模拟数据，值仅使用 0、30、60、90，生成后固定保存，不在运行时随机。
- 数据缺失按 0 处理；未来日期保持位置但格子留空且无提示。本地日期与周边界使用浏览器时区，不通过 UTC 日期字符串截断取日。
- 四档口径固定为 0、1–30、31–60、>60 分钟，共用主题 Token `--check-in-level-0` 至 `3`。浅色候选为 #EEEEEE/#CCCCCC/#999999/#666666，深色候选为 #2A2A2A/#484848/#737373/#A3A3A3，均为中性灰。
- 有记录的格子复用共用 Tooltip 与页面现有 Provider，支持 Hover 和键盘聚焦。提示两行为 `10-22 · 星期四`、`学习时长：45分钟`；超过一小时显示如 `学习时长：1小时15分钟`，整小时不显示 0 分钟。0 分钟与未来格子不创建 Tooltip。
- 组件入口、日历视图、纯日期/分档/文案逻辑与 JSON 在 check-in 目录内分别维护；不新增独立业务 module 或通用热力图框架。
- 同步 Newtab 与 UI 说明，明确模拟数据来源及替换位置。
- 按用户本次验收补充，将 Settings 历史清理标题缩短为 `Clear History`，同步入口说明，不修改功能逻辑。

## 用户验收步骤

1. 在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，加载或重新加载 `D:\GitHub\exts\dist\build\chrome-mv3`，打开新标签页。本次为生产构建，dev 稳定目录未更新。
2. 检查右侧卡片首行显示 `Daily check-in` 和唯一固定选中的 `JLPT` 项，没有 GitHub；卡片外框、三区布局和 Dock 保持原有位置。
3. 检查格子为 24 列、7 行，列内从周日到周六，最右列为本地当前周。早于模拟数据范围的日期为零记录灰色，当前周未来日期留空；模拟数据范围内应出现四档灰度。
4. Hover 或键盘聚焦有记录的格子，显示如 `10-22 · 星期四` 与 `学习时长：30分钟`、`1小时` 或 `1小时30分钟`；0 分钟和未来日期没有 Tooltip。数据与日期可对照源码 JSON 核实。
5. 打开 Settings，确认历史清理标题为 `Clear History`，帮助说明与清理行为保持原样；切换 Light、Dark、System，观察格子同步使用对应中性灰阶、Tooltip 沿用共用样式；再检查书签、Dock 及区域滚动未受影响。
6. 如需检查跨日更新，可在本地午夜前后保持 Newtab 打开或跨日切回标签页，观察当前周/未来日期随本地日历推进；未实际执行则记为未验证，不把自动化日期逻辑测试当作此交互已验收。
