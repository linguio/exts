## 背景

apps/extension/src/assets/brand 当前有 28 个 SVG，合计 580529 字节，WXT 将其复制进扩展产物。shared/brand/BrandIcon 通过扩展资源地址显示，现有消费者包括 Newtab 书签、Dock 收藏和 Media Download 记录筛选。

用户希望网站 SVG 从服务器下载并缓存到本地，减少随扩展分发的网站图标资源，确认使用 Lucide Globe 作为未缓存、加载中和失败时的共同占位。根 assets/brand 是 Exts 三端品牌源稿与正式派生资源，与此次网站图标迁移分开处理。

## 目标

后续在 Studio 中统一提供网站图标管理与查询页面，支持新增、查看/查询、修改和删除，并结合远端 SVG 存储与扩展本地缓存。保留已有 SVG 内容、主题与尺寸效果，缺图时使用已确认的 Lucide Globe 占位。当前暂停，不实施。

## 原静态发布方案草案（仅供恢复时参考）

以下范围、建议、排除项、Todo 和验收标准均属于方向调整前的未批准草案，不是当前实施要求。恢复时应围绕 Studio 管理页重写，再请求批准。

- 复用现有 Neon 项目，先只读确认区域、分支及 Object Storage 可用性；目标生产分支与桶名核实后再申请执行具体外部变更。
- 建议创建 assets 公开只读桶，将第三方网站与文字 Logo 上传到 brand/；上传需要凭据，扩展只获取公开资源，不携带写入凭据。
- SVG 原稿继续保存在现有 Git 目录，内容不修改、不重绘；保留 brand/exts.svg、扩展 Manifest PNG 图标、Globe 和基础操作图标随包分发，不上传根 assets/brand 的源稿、预览或 Icon Composer 工程。
- 生成一份静态图标清单，维护稳定图标标识、不可变文件地址及内容哈希。先上传新文件并确认可读，再发布清单，避免清单指向尚未上传的文件。
- 使用 Cache Storage 缓存清单和 SVG；业务逻辑归 shared/brand，保留消费者现有图标标识与 BrandIcon 尺寸、主题、可访问性语义；不将网络或缓存业务放入 shared/ui。
- 有缓存立即显示；缺少缓存才下载。新版本成功下载并缓存后再替换旧版，更新失败继续显示同一图标的旧缓存；Globe 只用于完全没有可用图像时，不代替已有缓存。
- 占位图通过现有 UiIcon 规则静态导入 Lucide Globe，不全量导入图标库，不加额外动画或失败 Toast，不影响书签点击。
- 检查实际图片解码失败及缓存读写失败：不把非成功响应或无效图片当成成功缓存；缓存不可用时不阻塞页面，联网时允许临时显示，后续访问可重试。
- 明确资源服务 CORS、扩展 CSP 与网络请求边界，能通过 CORS 访问时不新增 host_permissions；如确需声明权限，只覆盖核实后的资源服务来源，不申请所有网站或 unlimitedStorage。
- 远程与缓存流程通过必要验证后，取消迁移对象的 WXT 随包复制，保留 Exts 本地图标及全部源稿；同步应用 AGENTS 中资源复制规则、扩展 UI/资源说明与交付记录。

## 原草案验收标准（恢复时重写）

- 首次在线打开时，尚无缓存的网站图标显示 Globe，下载成功后显示原 SVG；尺寸、明暗主题和链接操作保持原有表现，不出现破图标记。
- 同一版本已缓存后，重复打开和浏览器重启均可显示图标，不重复下载 SVG 文件；清单检查遵循最终批准的频率。
- 缓存存在时离线仍显示已有图标；首次使用且离线时显示 Globe，书签、Dock 与下载记录的原有功能仍可操作。
- 清单有新版本时只获取需要更新的 SVG；下载失败、非成功响应或无效图片不会覆盖可用旧缓存。恢复联网后，后续访问能够重新尝试。
- SVG 源稿与远端文件内容一致，主题和 Exts 特殊显示规则不变；源稿保留在 Git，迁移对象不再进入正式扩展包，Exts 本地图标及其他必要资源仍存在。
- 扩展不含存储写入凭据，不增加所有网站权限；不存在数据库变更、付费升级或未批准的外部修改。
- 代理仅验证逻辑、HTTP/配置和构建；用户从根 dist/dev/chrome-mv3-dev-stable 加载开发扩展，或解压 dist/build/chrome-mv3 正式产物，在 Chrome/Edge 验收上述在线、离线、重启、更新及主题表现。产物路径以实际构建报告为准。
- 自动化验证、真实远端检查、浏览器用户验收与未验证限制分别记录，不互相替代。
