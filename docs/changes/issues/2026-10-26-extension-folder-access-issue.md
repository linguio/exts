# 区分文件夹遮挡并为 EDU 添加四位界面锁

## 背景
Newtab 的 UI 与 EDU 文件夹目前都用锁图标表示模糊遮挡，点击即可显示，无法区分轻度隐藏和需要输入码的界面锁。

## 目标
UI 保留一键显示的轻度模糊，EDU 通过固定四位 PIN `0000` 解锁；两者图标、操作及过渡清楚区分。

## 范围
- UI 文件夹用闭眼图标表示轻度遮挡，点击后切换睁眼图标；悬停不切换图标。
- EDU 文件夹用锁图标表示界面锁，点击后在文件夹遮罩内部只显示四个 64px 的密文密码块，采用与内部书签相同的 2×2 布局、横纵 16px 间距和四周 16px 留白，不弹出对话框或额外提示。采用 shadcn 官方 Input OTP；输满四位自动校验，`0000` 正确时锁图标切换为开锁，再淡出遮罩。错误输入立即清空四块，保持锁定且不播放成功动画。
- EDU 尚未成功解锁时，点击文件夹外部会退出输入、清空已输入内容并恢复锁图标；按 Escape 也可退出。成功解锁后焦点停在文件夹容器，下一次 Tab 可进入书签，不默认聚焦第一个书签。
- UI 与 EDU 使用相同过渡：图标交叉淡变 200ms、停留 200ms、整个遮罩淡出 200ms，总计 600ms。使用现有 CSS，不引入动画库。减少动态效果偏好下直接切换。
- 刷新 Newtab 后 UI 与 EDU 恢复初始遮挡状态；保留现有书签内容、顺序、链接、分组及打开行为。
- 固定 `0000` 是界面访问门槛；书签内容不加密、不增设 PIN 设置或重置，也不宣称能抵御读取扩展源码或存储的人。

## 验收标准
- UI 保持点击显示、无需输入；EDU 在原文件夹内部只出现 2×2 四个 64px 密文密码块，横纵间距 16px、四周留白 16px，与内部书签布局一致；不出现对话框或提示，输满后只有正确的 `0000` 才显示书签。
- UI 悬停时保持闭眼，点击后睁眼；EDU 悬停时保持锁，验证成功后锁转开锁，错误码清空四块且无成功动画。
- UI 与 EDU 都按图标变化、停留、遮罩淡出各 200ms 的相同过渡解锁；减少动态效果偏好下直接切换，刷新后两文件夹重新遮挡。
- EDU 锁定时不能通过键盘或其他普通界面操作打开被遮挡的书签；解锁后链接与分组行为保持。
- EDU 输入中点文件夹外部后恢复锁图标且不保留已输入数字；成功解锁后不默认聚焦第一个书签，下一次 Tab 可进入书签。
- 代理执行纯逻辑、类型、构建检查；用户在 Chrome/Edge 加载产物验收外观、输入、焦点和交互。

## 用户验收步骤
1. 在 Chrome 或 Edge 的扩展管理页加载或重新加载根 `dist/build/chrome-mv3`，打开新标签页；检查 UI 显示闭眼图标、EDU 显示锁图标，悬停两者均不换图标。
2. 点击 UI：闭眼切为睁眼用约 200ms，停留约 200ms，整个遮罩再用约 200ms 淡出；解锁后首个书签不应自动出现焦点描边，按 Tab 可进入书签。刷新后恢复模糊，检查 UI 原有滚动、书签顺序和点击打开行为。
3. 点击 EDU：原文件夹内部仅显示四个 64px 密码块，2×2 排列、横纵间距和四周留白均为 16px，与内部书签对齐；输入数字显示为圆点，页面无对话框、提示或确认按钮。输入非 `0000` 的四位数字，四块自动清空且 EDU 仍锁定；输入未满四位时点文件夹外部，输入区关闭并恢复锁图标，重新打开时四块为空。按 Escape 也可退出输入；锁定时 Tab 不应聚焦 EDU 书签链接。
4. 重新点击 EDU，输入 `0000`：四位输满后输入格收起、锁切为开锁约 200ms、停留约 200ms，整个遮罩再淡出约 200ms；解锁后第一个书签不应自动出现焦点描边，按 Tab 后可进入书签，书签可正常打开与分组。刷新后 EDU 重新锁定。
5. 切换 Light/Dark/System 主题检查输入框和遮罩配色；在系统减少动态效果下重复解锁，确认直接显示、不等待动画。Chrome/Edge 的实际外观、焦点和交互以用户验收为准。
