# 完善版本整理与全量验证流程

## 元信息
- 项目：repo
- 状态：已完成
- 规模：小型Skill与规范更新
- 批准依据：用户明确要求更新现有Skill，区分日常最小验证、普通提交复用结果和发版本全量测试。

## 背景与目标
更新产品版本代表准备一次发布，必须整理上一正式版本以来的变化，先展示版本与Changelog草稿供用户审定，确认后写入并完成全量验证，不能按两处文案配置变更仅验证官网。

## 范围
完善workflow-change、workflow-tests及测试Skill展示提示，关联验证规范、构建发布规范和根入口规则；保持单一事实来源。用户后续批准本地执行一次全量可运行检查，并要求全仓库只读扫描测试更新范围，将全量时审查测试适用性写入Skill。

用户进一步批准在本Issue内实施审查建议：更新9份Extension测试、清理无调用旧导航helper，补齐CI的官网/API/公共工具与完整原生测试入口，同步现行导航规范；不新建Issue。

## 排除项
不修改版本号、Changelog或其他产品功能，不升级应用依赖，不新增测试框架，不提交Git。CI仅补已识别的入口与所需精确Python测试环境，不接生产数据库或修改部署目标。

## 验收标准
- “更新产品版本／发版本”触发上一正式版本至当前交付的变化整理，先展示拟用版本号、Changelog标题、分类与正文草稿，等待用户审定后才写入并完成全量验证；已有明确审定内容不重复确认，仅总结不擅自写入。
- 日常开发按影响范围，普通本地commit复用结果且不补跑。
- 已知失败不能算发布验证通过；无法本机执行的检查标记待验证，不假称CI已覆盖。
- 不扩大为发布授权或自动修改CI，不重复维护全量命令清单。
- 全量时同时审查用例适用性、重复与入口遗漏，先列具体证据与更新建议，不未经批准清理测试。
- 原四项失败通过契约同步解决；实际路由恢复、账号隔离、请求取消与迟到响应覆盖保留，CI入口补齐但平台运行结果不冒称本地通过。
