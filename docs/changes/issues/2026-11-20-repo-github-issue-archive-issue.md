# 将已完结的本地工作项归档到 GitHub Issues

## 元信息

- 工作项：2026-11-20-repo-github-issue-archive
- 状态：实施中
- 当前阶段：已调整为仅归档完结工作项，待确认首条正式归档摘要
- 已批准范围依据：用户要求 GitHub Issues 只用于归档，本地继续维护开发过程与状态

## 背景与目标

本地 Markdown Issue 和交付记录管理开发过程。工作项完结后，将经确认的交付摘要归档到 `linguio/exts` 的 GitHub Issues。

## 拟议范围与排除项

- GitHub Actions 检查指定分支推送中的归档摘要变更，按稳定工作项 ID 创建或更新原 GitHub Issue、加统一归档标签并关闭。预览、发布、补录与重跑复用同一脚本。
- 公开摘要说明具体交付和使用者可见的变化，可链接到 GitHub 上可访问的对应工作项文档或相关源码。公开字段、触发分支及归档标签由仓库约定。
- 从一条已完结的本地工作项开始试点。GitHub Issue #1 是此前未完结工作项的试点，待对应工作项完结后可复用原编号归档。
- 本轮排除 Project、进行中状态同步、双向回写和官网展示。通用归档规则由 Skill 改造 Issue 维护。

## 验收标准

- 同一工作项多次补录、推送或重跑时沿用原 GitHub Issue。运行串行执行，创建结果不确定时先按工作项 ID 查找，再决定是否补发。
- 一次推送可以处理多份已确认归档摘要，同一条采用推送后的最终版本。仅本地已完结的工作项可发布归档，归档 Issue 带统一标签并关闭。
- Issue 已创建但标签或关闭失败时，重跑复用原 Issue 并补齐结果。
