## 背景与目标

本地 Markdown Issue 和交付记录保留在原路径，继续供 Agent 管理开发。为已完成工作项发布面向读者的 GitHub Issue 摘要，官网提供可筛选的交付记录和统计，详情跳转至 GitHub。

## 拟议范围与排除项

- Agent 从原件提炼公开摘要，经用户确认后提交。摘要包含归档 ID、公开标题、交付摘要、应用、类型和实际完成日期。
- GitHub Actions 监听指定分支上的摘要变更，调用脚本发布；保留手动入口用于历史补录，Skill 按实际需要另行考虑。源仓库与目标仓库、分支、公开边界及权限待确认。
- 已发布摘要如需更正，通过编辑公开摘要并推送更新原 GitHub Issue。使用稳定的工作项标识匹配，创建时在正文中写入归档 ID，归档打标签并关闭。
- 每日通过 GitHub REST API 分页读取归档 Issue，排除 PR，按 GitHub Issue ID 写入数据库。整批校验成功后更新快照，失败时保留上次结果。
- 排除迁移本地原件、双向状态同步和发布原文档。本次授权仅覆盖本地建档。

## 验收标准

- 同一工作项多次补录、推送或重跑仅对应一条 GitHub Issue；修订后保留原链接。发布任务串行执行，创建结果不确定时先核对归档 ID 再决定是否补发。
- 官网每天同步归档数据，重复同步不增加记录；完整同步失败时仍可看到上一份有效数据。
- 官网可浏览交付摘要并打开对应 GitHub Issue；历史补录按实际完成日期计入对应月份。
