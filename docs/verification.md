# 按变更影响范围验证

本文件维护仓库验证策略。根 AGENTS 保留强制入口；[tests Skill](../skills/tests/SKILL.md) 提供检查选择方法，不复制项目命令或建立第二套规则。用户最新明确要求及特定风险的现行要求优先。

## 按改动选择检查

| 改动 | 必要检查与边界 |
| --- | --- |
| 纯文档、Skill | 本次文件的格式、相对链接与规则一致性；Skill 元数据及相关场景审阅。不运行应用测试、类型检查或构建 |
| SVG、图片等静态资源 | 文件可解析、引用与生成输入正确；影响打包时构建所属应用。不运行无关业务测试或仅因资源修改运行类型检查 |
| 样式、界面文案 | 检查引用；修改 TS/TSX 时运行所属应用类型检查，影响编译或样式产物时构建。无逻辑变化不跑业务全量测试；视觉与交互由用户验收 |
| 局部业务逻辑 | 对应行为测试与所属应用类型检查；影响打包、运行入口或依赖图时构建。阶段完成不自动追加无关模块测试 |
| 跨模块行为、公共应用基础能力或大范围目录迁移 | 阶段结束执行所属应用完整测试、类型检查与构建，不重复执行已覆盖且仍有效的针对性检查 |
| 公共包、依赖或根构建配置 | 检查直接受影响包及其消费者；依赖升级仍按版本规则执行安装、测试、构建。只有影响确实跨越整个仓库时才扩大到全仓库 |
| 仅本地提交 | 不重新测试、类型检查、构建或附加文档检查；复用结果并按提交流程同步终态、核对暂存边界、提交和核对结果 |

目录数量、文件数量和测试数量不作为全量验证的触发条件。沿实际引用和依赖判断；不确定时先扩大到受影响应用。明确安全、权限、数据或兼容性风险需补充对应验证，不以等待时间为由省略必要风险检查。

## 完整检查与结果复用

- 完整功能检查只覆盖目标行为；完整应用检查只覆盖该应用；完整仓库检查才涵盖全部受影响应用与公共包。修改 extension 不默认检查 website、desktop 或 API。
- 影响面较大的开发交付需要完整应用检查；合并/发布时依据目标和现有门禁补齐必要检查，没有相关输入变化则复用结果，不因进入新阶段重复运行。发布打包和平台构建仍遵循构建分发规范。
- 代码、构建配置、依赖、生成输入、有关环境改变时，重新运行受影响且已失效的检查；无关文档变化不使代码检查失效。旧结果无法确认对应范围时如实标记未验证，不视为通过。
- 直接在现有 Issue/Commit 记录保存实际命令、范围、结果及限制，不建立额外的结果数据库或强制扫描流程。
- 需要重新检查时只运行一次相应范围；失败处理、一次定位与一次重试上限、内存告警熔断和串行执行继续遵守根规范。
- 用户要求本地提交后，不启动新的验证或 Skill 链，不追加浏览器验收，不阻塞在未执行的检查上；明确记录已有结果与未验证项。

## 控制长期成本

测试对应用户行为和真实架构边界，同一行为保留一个主要验证层级，不随任务不断积累重复测试、源码文本断言和额外守卫。不因本策略顺手重写或清理无关测试。

优先使用现有功能测试、应用边界与真实依赖划分影响。按路径配置 CI、构建缓存和慢测试管理是可选的后续独立工作，本规范不代表这些能力已配置，也不自动批准新增工具或 CI 改动。

用户负责 Chrome/Edge 视觉与交互验收；代理只验证逻辑、配置、构建和必要边界。自动化通过不等于用户验收通过。
