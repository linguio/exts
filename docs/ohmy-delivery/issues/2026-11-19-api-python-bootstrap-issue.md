## 背景与目标

现有apps/api/scripts/dev.mjs已共用环境创建、依赖同步、配置检查与服务启动流程：macOS/Linux使用python3.12，Windows在没有虚拟环境时只使用py -3.12。

用户Windows上的Python由uv安装，版本为3.12.13。python3.12可运行，py -V:Astral/CPython3.12.13也可运行，但py -3.12无法找到对应运行时，导致脚本在创建环境前退出。安装启动器不能单独解决选择方式不兼容。

目标：用户自行安装指定版本Python并准备必要API配置后，两端均只需执行pnpm api:dev；缺少项目虚拟环境时自动创建、安装依赖并启动，后续复用。macOS当前源码已有该流程，不把Windows兼容修复扩展为另一套环境管理。

## 范围与排除项

- 优化项目启动脚本的解释器发现，Windows兼容传统Launcher与现有uv安装；优先沿用当前入口，失败或版本不符时尝试PATH中的python3.12等已安装解释器，找到后仍严格核对精确版本。实施时不硬编码本机路径或Astral厂商标签，不要求额外安装uv。
- .python-version继续作为唯一版本源，当前3.12.13，不自动升级、下载或安装系统Python/Launcher，不接受其他补丁版本代替。
- 保留macOS/Linux既有行为、根pnpm api:dev与应用dev入口、现有环境目录dist/.cache/api/venv、依赖摘要同步、配置预检与uvicorn启动。
- 已有有效环境直接复用；已有环境版本不符或创建/安装失败时明确报错，不删除、覆盖或自动重建已有环境。解释器探测失败可继续寻找候选，最终失败要区分缺失、版本不符和执行失败，避免一律误报未安装。
- 补充现有启动行为测试并同步API README及docs/build-release.md；后者“需要手动创建环境”的旧描述与实际自动创建不符，应修正。
- 不改本机PATH/注册表，不重装Python，不修改业务接口、认证、数据库、迁移、依赖或发布版本，不处理当前目标以外的构建/发布改造。
- 用户已批准继续实施本Issue的启动脚本、行为测试和维护文档修改。不自动Git提交、推送或部署，不为验收启动长期后台服务。

## 验收标准

- Windows在本机uv Python 3.12.13可用、py -3.12不可用且项目环境不存在的情况下，执行pnpm api:dev能够自动创建环境、同步依赖、检查配置并启动；无需先手动执行venv命令。
- macOS/Linux在python3.12为精确指定版本时保持同样流程；没有实机验证时只记录已有源码/逻辑测试结果，不声称实机验收。
- 已有环境且依赖未变化时不重复创建/安装；依赖清单变化仍按原摘要同步，不增加第二套缓存或配置。
- 所有解释器都不符合要求时，停止并明确说明精确版本要求；不自动下载或选用其他版本，不运行服务或数据库操作。配置缺失、创建失败、安装失败继续停止在对应步骤。
- 根命令与目录规范保持；测试只验证进程决策及真实环境准备边界，不引入假DOM/视觉测试，不为该局部修复重复运行整仓产品发布检查。
