# 统一取消扩展焦点描边并清理补偿逻辑

## 当前阶段

已完成。

## 目标与范围

### 背景

扩展的浏览器及 shadcn/Radix 焦点反馈与局部补偿并存：Dock 使用 useDockOverlay 和 data-restored-focus 隐藏恢复焦点后的描边，部分弹层通过主动聚焦标题避开默认反馈。逐处处理增加维护成本，也使不同入口表现不一致。

### 目标

清理局部焦点反馈补偿，描边规则集中维护并按用户最新要求启用；共用 Tooltip 统一只响应鼠标悬停，不因聚焦自动打开。保留真实焦点、键盘操作与业务行为，业务页面不再为相同目标增加补丁。

### 范围

- 当前 apps/extension 的全局焦点外观：核对 outline、Tailwind ring 和自定义入口焦点样式，在一处集中维护取消规则，不逐页覆盖。
- 清理 Dock useDockOverlay 中仅为描边抑制维护的标记、状态和事件，以及失效的调用参数和配套 CSS；不因删除 Hook 而移除必要业务状态。
- 核对 Settings、About、Download、表格编辑的 onOpenAutoFocus：移除仅为避开描边添加的标题聚焦覆盖；若同时承担其他功能，不机械删除，记录实际依赖。
- 核对与上述补偿绑定的 Tooltip 抑制，移除失效接线；用户追加批准在共用 TooltipTrigger 一处阻止聚焦触发，保留鼠标悬停与官方关闭行为，不在业务页面新增处理。现有打开时互斥与业务条件继续保留，不机械删除。
- 用户追加批准共用 SheetContent 打开时统一聚焦面板容器，不自动聚焦或选中首个输入框；不新增 Hook，不在 Daily 等调用方增加处理，Dialog 不在本轮调整范围。
- 保留 Radix 默认焦点恢复、键盘导航及实际需要的弹层焦点交接，不新增统一 Hook、全局 focus 拦截或 blur 补偿。
- 用户追加批准将通用交互统一维护原则写入根 AGENTS.md；禁止业务页为同类反馈逐处累积补丁，不引入无必要管理层，业务与环境适配不混入清理。
- 实施时同步应用规范与 docs/web-ui-sources.md：明确全局不显示焦点描边，禁止业务页面为相同目标添加补偿，替换要求保留旧补丁的现行记录。

### 排除项

- apps/website、apps/desktop、archive 及第三方依赖源码。
- 普通边框、普通阴影、错误提示、选中反馈及已确认主题与布局重设计。
- 右键菜单拦截、未保存修改确认、书签密码操作、Toast 复制等业务功能。
- ToggleGroup 选中反馈修补、Telegram Shadow DOM/系统选择器适配及其他独立兼容处理。
- 禁用所有辅助语义、删除其他公共 Hook、引入依赖、产品版本或 Changelog 更新。
- 推送或发布；本地提交已由用户“验收通过 commit”明确批准。
