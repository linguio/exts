## 交付记录

用户要求盘点扩展的加载状态并将居中要求写入规范。

- Home 活动日历、趋势和左右统计区使用共用 LoadingRegion，首次 Skeleton 区域占位，刷新 Spinner 在各自块内居中。
- Studio 账号 Spinner 有双轴居中类，但通过滚动容器渲染，实际位置依赖其视口内部高度，用户报告刷新时未居中，待单独验证。
- 字典组列表、字典项和共用编辑 Sheet 的 Spinner 按设计在各自区域居中。分组首次加载且没有选中项时，两栏当前会同时显示分组 Spinner。
- Daily 首次加载按正文剩余高度居中，共用 DataTable 刷新时的 Spinner 定位在整个 tbody，长表滚动时不能保证在可见数据区居中。
- Download Sheet 首次读取使用列表顶部文字，尚未采用居中区域 Spinner。设置行、登录或保存操作的反馈留在原控件。
- 规范新增可见区域定位和 Skeleton、控件反馈的边界。只做源码与文档核对，未执行 Chrome/Edge 视觉验证。

### 页面修正

- Studio 账号初始化直接由右侧正文空间承载居中 Spinner，期间不挂载正文 ScrollArea。字典分组首次加载且无选中项时仅左栏展示该请求的 Spinner。
- DataTable 将刷新 Spinner 放在滚动容器外，按实测表头高度避让表头，旧记录和滚动位置不参与居中。Download 首次读取改为工具栏下方的居中 Spinner。
- 扩展类型检查通过，相关逻辑测试 5 个文件、27 项通过，Chrome MV3 构建成功。构建有主题脚本及大分块警告，浏览器实际位置未验证。
- 验收时刷新 Studio，确认账号 Spinner 在右侧正文中央；在 Daily 有多页记录时先滚动再查询，确认 Spinner 留在可见表头下方；打开 Download，检查记录区居中；打开 Dictionaries，检查首次分组 Spinner 只出现于左栏。
