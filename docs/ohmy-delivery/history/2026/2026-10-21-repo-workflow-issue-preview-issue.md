# 明确建档展示与提交收尾规则

## 当前阶段

已完成。

## 目标与范围

### 背景

TG 工作已先创建 Issue 和 Commit 记录，但未在改代码前向用户展示链接和实施范围。现有 workflow-change 规定先建档，却没有明确展示时机，需要补足执行规则，而非仅依赖本会话记忆。

### 目标

将“先展示，再实施”固化进仓库 Skill；提交阶段复用已有验证，已有明确批准时不额外制造确认步骤，拆分历史前说明远端状态和同步影响。

### 范围

- 修改仓库真实源 skills/workflow-change/SKILL.md 及配套流程参考，同步根 AGENTS 和工作台规则，消除相互矛盾的提交条件。
- 明确建档完成后、修改代码或配置前，先展示 Issue 链接、已批准范围、唯一下一步。
- 已有实施批准时展示后继续，不重复索要；仅建档不等于已向用户展示。
- 现有发现链接保持原样，不另外复制全局 Skill，不写长期记忆。
- 提交收尾只做必要记录、diff 与消息核对及本地提交；已有验证且相关内容未变化时不重跑测试、类型检查或构建，不重新调查或重复确认。
- 用户明确免除后续验证时遵从，如实记录未执行事项。
- 用户补充：明确要求“提交到本地”即表示当前 Issue 可以完结，不核实用户是否验证，不以看过交付材料为前提，不追加验证或重复请求验收；随提交同步 Issue、Commit 记录和工作台为完成状态。提交失败时恢复待提交状态，未执行事项如实记录。
- 拆分提交前说明文件边界、消息、远端状态及分叉影响；远端覆盖须单独获准并使用带预期远端提交限制的 force-with-lease。

### 排除项

不修改其他 Skill，不新增审批门禁或文档层，不安装工具，不运行模拟开发或子代理，不改 TG 实现或体积规则。
