# 表格规范

本文件是仓库级长期规范，与[业务 API 规范](./api-conventions.md)、各应用 UI 规范并列。适用于官网、浏览器扩展的业务表格及其列表查询接口；原生桌面复用业务与接口语义，控件及视觉采用平台规范。

新建、接入或调整表格前必须查阅本文件。表格行为、列表查询契约和默认值在此维护；主题、材质及官方组件来源由 UI 规范维护；认证、HTTP、通用响应和异常由 API 规范维护。业务字段、业务默认筛选和具体排序白名单由各接口及业务说明维护，不在页面另建一套通用规则。

## 维护与适用边界

- 本规范持续维护，不是某个 Issue 的交付总结。以后表格需求与验收发现共性规则时，经用户确认后同步本文件；接口、组件和用法变更同步相关文档，不只留在聊天或历史 Issue。
- 默认规则作为后续表格的基线。业务差异必须在对应 Issue 和长期业务说明中明确用户批准的原因、范围及行为；不得凭代理偏好覆盖默认规则，也不得因业务例外改掉所有表格的行为。
- 尚未确定的能力只能记录为待讨论，不作为已批准规范；已有代码不因规范建立即自动视为合规或已验收。
- 本次规范整理不批量改造现有调用方、不新增依赖或公共框架。新表格按规范接入；已有差异在对应获批任务中逐项落实。
- 复用改造围绕现有 DataTable 渐进完成：保留已有列定义、筛选类型、渲染、分页、排序及必要组合入口，只收拢当前确实重复的流程。新增、编辑、删除、多选及批量操作有实际需求时再逐项补齐，不要求一次建设完整 CRUD，不预建占位接口、插件系统或未来框架；升级空间通过清晰职责和既有配置/组合能力保留。

## 组件与职责

- Web 控件采用 shadcn 官方组件及其组合，复用应用已有 DataTable、主题 Token 和状态反馈；不在业务页面仿写表格、分页、列显隐或加载控件。
- 复用同一应用的通用组合，不为形式统一新增跨应用组件包。官方原语保持可追溯，项目确认差异放在组合层并记录来源。
- 底层 DataTable 负责渲染和基础交互；统一业务表格入口负责查询草稿/已生效条件、请求生命周期、通用操作与 CRUD 编排。业务资源侧只提供字段、筛选、接口适配及必要元数据/权限/校验，不让每个页面重新实现共同流程。通用能力不包含具体账号、Chrome 消息类型、业务字段或接口路径。
- 业务接口数据默认采用服务端分页/筛选/排序。完整、小型内存数据集可以采用本地模式；不能把接口当前页当成全部数据进行本地筛选、排序或统计。
- 每行使用稳定业务标识，不以当前页数组下标作为 ID。

## 配置驱动与单一维护原则

**普通业务表格必须以配置接入，共同的查询与增删改流程只维护一份。不能让每个页面通过大量定制操作完成相同的工作。**

本节是普通业务接入约束，不表示所有应用或 CRUD 已完整落地。扩展现已提供 QueryDataTable 并迁移 Daily，将查询草稿、生命周期与标准工具栏收进共同能力，实际浏览器效果待用户验收；其他应用及新增/编辑/删除按真实需求逐项实施。

### 业务只提供的配置

| 配置类别 | 允许包含的业务信息 |
| --- | --- |
| 字段 | 字段标识、标题、数据/控件类型、格式化、可排序/可筛选/可编辑、必要校验与选项；可选 `edit.unit` 仅作编辑 Sheet 内展示；显示字段和可写字段必须明确，不凭字段名猜测 |
| 查询条件 | 文本/选项/日期等类型、参数含义、默认值及必要联动数据，不包含每页自定义的 Query/Reset 实现 |
| 接口 | 查询及实际存在的新增/更新/删除能力，参数和响应映射、业务数据校验；接收公共层传入的 signal，查询适配返回 rows/total |

行标识、表格名称、数据作用域、必要能力/权限开关属于少量资源元数据，随配置提供。没有特殊要求时使用统一默认布局和交互，不要求每个页面重复传入按钮、加载、分页和重试实现。

### 必须由共同能力维护的流程

- 草稿与已生效条件、Query/Reset、排序/分页联动、默认值恢复和列显隐，不能每页编排一套状态。
- 请求开始/结束、loading/error/retry、取消在途请求、迟到响应防护、已有结果保留及作用域变化清理，不能每页复制 Effect、AbortController、请求序号和状态循环。
- 请求取消由共同能力创建和管理，接口适配只转交 signal；即使接口不能及时取消，也必须阻止旧响应覆盖新状态。
- 复用已有认证、超时、HTTP 错误和后台消息传输能力，不再新增一套通用请求框架。业务数据权限和接口校验继续由资源及后端执行。
- 已批准的普通新增/编辑共用表单承载、打开/关闭、回填、校验呈现、提交中状态、防重复提交、成功关闭/刷新和失败保留输入流程。编辑类任务默认使用官方右侧 Sheet；简短提示与简单确认使用 Dialog；删除或放弃未保存修改等有损操作使用 AlertDialog。Daily 演示编辑已落地，其他存量页面不在本轮批量改造。
- 已批准的删除共用确认、pending/失败/成功反馈与刷新/页码校正；普通操作列和可选批量操作按字段/接口能力/权限配置接入，不每页复制按钮与状态机。
- UI 状态、提示和更新时机在共用流程中维护；业务只返回约定结果或可识别错误，不在每个查询/写操作后手动拼接 loading、关闭、toast、reload。

### 约束与扩展边界

- 普通列表页面应主要是配置与统一入口调用，不再单独实现标准工具栏、请求 Effect、取消、错误重试或表单/删除确认状态。
- 不用大量每页 renderToolbar、onQuery、onReset、onSubmit 等任意处理器把标准流程重新交还调用方；有共同规则的行为先在共用能力实现。
- 不能反向把业务接口路径、令牌、Chrome API、字段名称或后端权限写进通用控件。共同生命周期与业务资源适配是不同职责；配置入口不要求全部逻辑塞进一个文件。
- 不新增另一套重复表格引擎；复用现有 DataTable 作为基础，标准业务入口只补缺失的共同编排。
- 普通行编辑由列 `ColumnDef.meta.dataTable` 声明筛选与编辑配置：字段标识与标题沿用列定义，未声明 `edit` 的列不可编辑；`readOnly` 可展示且不进写 payload；`disabled` 展示但禁用，不进校验与 payload，不能单独触发行末 Edit。QueryDataTable 仅在可写字段且（`updateFn` 或显式 `previewEdits`，默认 false）时开放 Edit。预览补丁只作用于当前成功响应且与在途查询 key 一致时；`updateFn` 成功后组合层刷新。资源适配在 `query.ts` 等入口只提供查询（及未来的真实更新），不复制 toast/关闭流程。
- 未提供写接口的表格默认只读；经明确批准并显式开启 `previewEdits` 后，可在共用层对当前返回记录做临时编辑，不建立第二查询数据源、不伪造 total 或重排服务端当前页。后续查询以接口结果为准。配置化改造不自动授权新增所有资源的 CRUD API、权限或数据库结构。
- 复杂业务确需额外流程时，先确认其真实差异并记录批准；不能把常规分页、查询、保存和删除称为“业务特殊”而逐页重复维护。

## 布局与显示

- 默认表头和内容居中，在通用表格组合层维护。业务确需其他对齐时先明确并记录，不逐个页面复制覆盖。
- 默认顺序为查询工具栏、表格、分页页脚。查询条件位于工具栏左侧；右侧为官方 ButtonGroup（Query 文字、Reset 图标）与紧邻独立的 Columns 图标列显隐菜单，同一行排列，图标按钮提供可读名称与提示。排序入口在表头，不另设独立排序配置区。
- 常规宽度下相关控件同行排列；窄屏只能以完整控件组换行。例如标签与选择器、页码输入与 Go 不拆开。
- 宽表沿用官方 Table 自带横向滚动，不机械嵌套 ScrollArea。其他滚动需求遵循根 UI 的官方优先选型，不维护业务专属滚动条。
- 表格保留无障碍名称，即使隐藏可见 Caption；按钮、排序、页码、输入和加载状态具有可读名称。
- 分页的可见文案与无障碍名称统一英文；其余文案遵循应用与业务的语言约定，不混用同一控件的名称。

## 加载、空结果与失败

- **表格不使用骨架屏。首次和刷新统一使用官方 Spinner。** 模块级 LoadingRegion 的“首次 Skeleton、后续 Spinner”规则不适用于表格。
- Spinner 定位在整个 body 的水平与垂直中央，只显示图标，没有可见文字；保留读屏名称和 aria-busy。
- 加载不替换表头、工具栏或页脚，不在顶部新增提示行，不因 Spinner 插入而挤动原记录。首次以空白 body 承载 Spinner，刷新保留当前账号已有记录。
- 不添加毛玻璃、背景覆盖、透明度材质、新加载 Token 或计时器。加载状态由真实请求生命周期驱动，不用人为延迟制造效果。
- 加载中的空数组不是成功无记录，不提前展示 Empty。成功无记录与筛选无匹配应按语义提供官方 Empty 组合。
- 查询失败不在表格内容区占用 Alert 或内联错误文案；表格保持表头/工具栏/分页，body 展示空数据（官方 Empty 或业务 emptyContent），工具栏 Query/Reset 仍可重新发起查询。失败经应用统一的右下角 Sonner `toast.error` 提示，使用简短中文安全文案（例如「查询失败，请重试」），不向用户展示原始连接错误或环境说明（例如本地服务是否启动）。内部仍保留错误状态，不把失败标成查询成功，也不在失败时清空行数据以外把 `total` 归零以免分页自动回退触发额外查询；成功无记录与失败空表语义分离。重试使用失败时已生效分页/筛选/排序（草稿不变）；成功响应总数收缩时仍允许共用层按规范回退页码。
- 请求变化时取消旧请求并忽略迟到响应；退出、换号和会话重置不展示旧账号内容。刷新保留仅为当前展示内存状态，不等于新增持久化或查询缓存。

## 查询与筛选的默认行为

- 业务表格默认手动查询：筛选输入只修改草稿，点击 Query 后成为已生效条件，并回第一页；当前用户排序和每页条数保留。
- 排序、翻页与修改每页条数立即查询，使用已生效筛选，不顺带提交未点击 Query 的草稿；草稿继续保留。
- 如需即时搜索/即时筛选，必须在业务任务中明确生效时机，不静默混用两种模式；本地开发示例的即时控件不代表业务默认规则。
- Reset 将草稿和已生效筛选恢复业务默认值，清空用户排序，回第一页并立即查询一次；保留每页条数和列显隐。不按状态字段逐个发请求。
- 初始化默认第一页、每页 20 条。默认筛选及默认顺序须在业务契约中明确；无批准的默认限制时，不隐式添加“最近一周/月”等日期条件。
- 列显隐立即生效，不请求后端、不改变筛选和排序，不被 Reset 清除；至少保留一个数据列，业务必需列可禁止隐藏。隐藏列不等于取消其已生效排序。
- 日期筛选必须声明对应业务字段、格式、时区和首尾边界，不能把业务 date 自动解释成 createdAt；不把 Daily 的日期字段强加给其他业务。

## 表头排序

- 沿用 TanStack 默认表头交互：普通点击进行单列排序，Shift 点击组合多列；multiSort=false 时只允许单列。不自行增加普通点击总是累加的行为。
- 排序条件按数组先后确定优先级，前一字段相同时才比较后一字段；先选字段优先，前端保持顺序传给后端。
- **默认排序属于后端兜底，不预置到用户排序数组中。** 初始化、Reset 和清空排序时前端保持空数组，由后端使用业务默认顺序；不让默认唯一字段占第一位，使后续用户字段失效。
- 用户显式选择日期或其他唯一字段时，该字段按选择优先级生效。唯一字段排在首位时，后续字段不会改变顺序；不悄悄改写用户显式优先级。
- 服务端在用户排序末尾补充必要的稳定字段；不得放在用户字段前面，也不重复追加已有字段。稳定字段由业务定义，不一律要求 date。
- 排序变化回第一页；表头显示用户实际选择的方向。未主动排序时不伪造已选择条件。
- 哪些字段可排序必须与后端白名单一致；操作列、选择列等非数据列不提供排序。

## 分页与页脚

| 项目 | 默认规则 |
| --- | --- |
| 页码 | 前端/API pageIndex 从 0 开始；界面展示和输入从 1 开始 |
| 每页条数 | 默认 20；Daily 等业务可选用 20、50、100（无 10）；接口上限 100 |
| 页脚内容 | 筛选后总记录数、当前页/总页数、Rows per page、页码导航、Go 跳转 |
| 导航名称 | First、Previous、Next、Last；条数与跳转各自保持完整控件组 |
| 总页数 | ceil(total / pageSize)，使用筛选后总数，不使用当前页数组长度 |
| 翻页 | 保持已生效筛选、排序和每页条数 |
| 改每页条数 | 保持已生效筛选与排序，回第一页 |
| 跳转 | 只接受 1 到总页数的整数，校验通过后转换为 pageIndex=页码−1 |
| 边界 | 首页/末页不可越界；空结果不跳转；一页时只有 1 是合法页码 |
| 总数缩小 | 响应确认后，将越界页回退到最后有效页；加载时不拿旧总数提前回退 |

页脚不强制未知总数或游标分页。当前基线是有准确 total 的页码分页；其他模式在出现实际需求并获批后完善规范，不提前增加框架或兼容层。

## 列表 API 参数与默认值

遵循业务 API 规范的 POST、JSON 请求体、camelCase 和认证约束。以下为列表查询基线，不适用于单记录读取、设置读取等非列表接口。

```json
{
  "pageIndex": 0,
  "pageSize": 20,
  "sort": [
    { "field": "readingMinutes", "order": "desc" }
  ]
}
```

- pageIndex/pageSize 必须同时传入启用分页，或同时省略进入接口明确支持的不分页模式。不能只传一个，也不能因参数缺失意外返回全部历史。
- pageIndex 为非负整数，pageSize 为 1–100 的整数；不把字符串、布尔值或小数转换成合法页码，不静默修正非法参数。
- 前端分页默认值是 0/20，由前端明确发送；后端不靠隐藏默认分页和不分页模式混用。
- sort 是有序数组，每项 field/order；order 仅为 asc/desc。省略或空数组使用接口定义的默认排序，不对所有业务统一固定日期倒序。
- 后端校验可排序字段白名单、重复字段和方向。字段映射到固定数据库列，查询值参数化，不接受任意 SQL、表名或列名。
- NULL 与 0 保持区别。可排序空值默认无论升降序都放最后；业务对非数值类型有不同规则时必须明确。
- 筛选参数由业务定义，不强行增加通用 filters DSL、全字段搜索或任意条件表达式。接口必须支持前端实际开放的条件。
- 身份和数据权限始终由后端验证；客户端 userId、total、列显隐和行选择不能作为授权依据。

## 不分页与数量上限

- 不分页必须是业务明确允许的模式，并约定必要的查询范围条件；不提供无限量列表读取。
- 新列表接口默认不分页最多 **500 条**，上限由后端具名常量集中维护，不散落业务代码；当前不为该固定值增加环境配置。需要不同上限时作为明确业务差异批准并记录。
- 匹配记录不超过上限时返回完整结果；超过上限返回 422，提示缩小范围或分页。不得静默截取前 500 条，让图表或调用方误认结果完整。
- 分页查询的筛选后总数不受 500 条限制，只受每页上限约束；不允许通过超大 pageSize 绕过限制。
- 不分页是否允许无筛选、单边日期、某个固定资源范围，由业务契约明确，不把“必须日期范围”作为所有列表的通用要求。
- days 的具体约定：不分页必须完整 startDate/endDate，按业务 date 筛选且包含首尾；最多 500 条。分页日期可选；默认 date desc，用户排序缺少日期时在末尾追加 date desc。图表明确传日期升序且不分页。

## 列表 API 返回与执行

```json
{
  "data": {
    "days": [],
    "total": 0,
    "pageIndex": 0,
    "pageSize": 20
  }
}
```

- data 下的集合字段由资源契约固定，例如 days；不为统一规范擅自把已约定字段改成 items，也不允许同一接口随模式更换集合字段。
- total 是当前用户/权限范围在全部筛选条件下的总记录数，不是当前页条数，不是所有账号总数；必须包含空结果或越界空页的正确值。
- 分页返回有效 pageIndex/pageSize；不分页两项返回 null，total 等于完整返回记录数。客户端不能把部分结果用作完整统计。
- 无匹配返回成功空数组、total=0；越界页返回成功空数组和真实 total，不冒充未登录或依赖失败。
- 后端先执行身份/权限过滤和业务筛选，再排序，最后分页；总数与当前页使用相同条件和一致快照。不先取全量到前端切片。
- 数据库执行方式由 API 分层规范负责，不为此规范强制新增查询框架、ORM、数据库结构或跨请求快照机制。
- 错误沿用统一 error 结构和真实 HTTP 状态；非法分页/排序/筛选或超过不分页上限为 422，认证、权限和服务故障遵循业务 API 规范。
- OpenAPI 请求/响应模型和示例来自实际实现；接口契约变化同步消费者与相关行为验证，不只改文档或类型声明。

## 选择与操作列

- 行选择默认关闭，按实际需要启用；服务端模式只表达当前响应范围选择，不把当前页全选宣传为所有查询结果全选。
- 切换账号、数据作用域或筛选后清理旧选择；刷新或服务端换页遵循现有选择契约，不把旧行标识误用于新记录。
- 普通操作列由统一业务表格入口按实际接口能力和权限配置组合官方 Button/DropdownMenu，确认、提交状态、结果提示与成功后刷新复用共同流程。资源侧提供接口和业务权限/校验规则；特殊展示可使用 ColumnDef.cell，但不能借此重新复制常规 CRUD 编排。
- CRUD 的普通交互只维护一套：表单类新增/编辑使用官方 Sheet，简短提示或简单操作使用 Dialog，删除与放弃未保存修改等有损确认使用 AlertDialog；不由每个页面选择不同承载方式。当前已实现配置驱动的行编辑组合并在 Daily 以真实查询加当前响应预览验证，复杂编辑、新增/删除流程及真实后端写接口仍未实施，不把统一规范描述成完整 CRUD 已交付。

## 后续接入与验证

- 新表格先核对本规范，再在业务任务中明确列、默认查询、排序白名单/兜底、是否分页、允许范围、数量上限及异常行为；不要每次重新发明通用交互。
- 同一需求涉及前后端时一起核对筛选含义、字段命名、排序优先级、页码基准和总数；业务日期与创建时间不得互换。
- 逻辑检查对应真实风险：参数与权限边界、查询状态、排序优先级、总数/分页、空结果、超限和迟到响应；不增加源码文本、像素、布局或模拟第三方控件交互的测试。
- 按[验证规范](./verification.md)选择影响范围，文档调整不触发代码测试或构建；浏览器视觉/布局/交互由用户在 Chrome/Edge 验收。
- 验收发现缺口时先判断属于通用规则、业务差异还是实现问题；获批后更新对应事实来源。未完成能力和待讨论方向不包装成已交付标准，不因维护规范扩大当前实现范围。
