# Settings 存储改造计划

对应 [Issue](../../changes/issues/2026-10-24-extension-settings-storage-issue.md)。用户已批准结构和实施，不新增独立 Spec。

## 设计与边界

- shared/storage 提供顶层对象串行读写与订阅；shared/settings 管理 settings 格式校验、默认值、旧键迁移和客户端。后续 downloads 复用公共机制，各自管理业务格式。
- 后台先注册消息监听再异步初始化；读取与写入共用串行入口，初始化不能覆盖并发更新。
- 业务模块保留业务判断；历史清理权限必须在用户手势内申请。
- 主题缓存只用于同步首屏，正式值从公共配置恢复；旧缓存仅在没有正式主题时迁入。
- 不更改界面、权限、依赖、下载保存或目录句柄。

## 实施顺序

1. 增加默认初始化、迁移、并发更新、失败恢复的逻辑测试，再实现存储仓库。
2. 注册后台消息入口，提供 getSettings、updateSettings、subscribeSettings；通过后台合并写入。
3. TG 和历史清理接入；主题异步保存并更新首屏缓存，复用现有错误提示。
4. 调整既有行为测试，执行一次完整测试、类型检查和生产构建。
5. 同步现行说明、记录实际验证和限制，提供 Chrome/Edge 验收步骤后停止。

## 验证

- 逻辑测试验证首次默认值、旧值保留、新值优先、并发不覆盖、失败不清旧值和后续恢复。
- 保留历史清理权限与事件行为覆盖，不调用真实历史删除 API。
- 用户加载 dist/build/chrome-mv3，验证持久化、跨页面更新、TG 开关与主题首屏。
- 不执行视觉或交互自动化，不创建 Git Commit。
