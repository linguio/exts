## 决策场景与基线

| 场景 | 现有证据或缺口 | 交付要求 |
| --- | --- | --- |
| 问答或普通聊天 | 旧入口不建档，但没有 Observer 边界 | 不观察、不写日志、不创建工作项 |
| 明确文案修正 | 授权范围延续未明确 | 直接按已批准范围执行，不重复询问 |
| 活动任务追加范围 | 旧入口只有继续活动工作项的笼统规则 | 区分当前补充与独立目标，同步用户批准范围 |
| 拆分与提交部分失败 | 旧参考偏重单笔提交 | 保留成功提交，只处理未完成部分 |
| 提交消息核对 | 旧入口要求提交前用 git log 检查 | 提交前核对待用消息，提交后核对实际消息 |
| 跨会话恢复 | 旧入口未要求检查分支、现有改动与提交 | 从仓库事实恢复，不擅自认领或删除已有改动 |
| 重复观察 | 尚无观察机制 | 重复仅补充证据，不自动认定偏好或需求 |
| 首次记录与月度提醒 | 尚无持久状态 | 首月积累，后续有有效新证据才提醒，当月最多一次 |
| 暂缓与缺少日志授权 | 尚无规则 | 无新证据不催促，未获授权不自行持久化 |
| Superpowers 不可用或要求冲突 | 当前 Skill 未明确配合 | 可独立执行，目标仓库约束优先 |
