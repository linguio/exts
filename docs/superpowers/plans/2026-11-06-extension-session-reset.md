# 登录初始化与退出重置实施计划

**目标：** 退出后扩展内不残留上一会话的信息，主动重新登录视为全新会话。

**设计：** [登录初始化与退出重置设计](../specs/2026-11-06-extension-session-reset.md)

**边界：** 只清理扩展自有数据；不删除已下载文件、第三方网站数据或云端 Activity。当前 Issue 完成后由用户验收，再决定提交。API 连接池参数独立处理。

## 影响位置

- `features/account`：后台认证操作与统一重置顺序。
- `features/activity`、`lib/api`：会话代次、请求取消与旧响应拦截。
- `features/settings`、`features/media-download/records`：清理期间阻止旧写入。
- `features/media-download/telegram`：中止在途下载，清空内存目录及专用 IndexedDB。
- `src/app` 和账户调用方：多 Newtab 原地同步账号与业务状态；登录恢复不触发重置。
- 本 Issue 与交付记录：写入实际结果和验证限制。

## 实施顺序

1. 后台引入单一会话重置协调对象；进入重置时切换代次、阻止新旧业务写入并取消 Activity。用同账号重新登录和迟到响应验证代次逻辑。
2. 给 Telegram 下载增加可取消的流处理与重置消息；已有页面定向清理 `exts-telegram-download`，无页面时临时非活动标签页执行同一动作。清理成功才继续；失败不得报告退出成功。验证下载停止、目录删除及旧完成消息被拒绝。
3. 统一清理扩展 `chrome.storage.local`、主题 `localStorage` 与 OIDC 凭据；先处理登录前业务重置，再处理退出的认证撤销、清理和页面状态同步。清理期间的设置、记录写入必须被拒绝或等待结束。验证登录取消、退出失败及重试。
4. 仅运行当前行为相关的逻辑测试、扩展类型检查与构建；记录自动化结果和未验证的真实浏览器场景，交付用户在专用 Chrome／Edge 配置文件验收。

## 停止点

- 不运行真实浏览器数据清理或视觉交互验收。
- 不自动创建 Git Commit、关闭 Issue、推送或部署。
- 若 Telegram 来源清理无法按已批准边界实现，不用整站清理代替；保留失败状态并说明阻塞。
