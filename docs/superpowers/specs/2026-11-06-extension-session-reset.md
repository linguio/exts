# 登录初始化与退出重置设计

## 目标与边界

每次主动退出后重新登录均视为新会话；相同用户 ID 也不得读取或显示上一会话的本地数据。单纯打开 Newtab 并恢复有效登录不触发重置。成功退出必须清除扩展持有的上一会话信息，不以页面重新渲染代替删除。

已下载到电脑的文件、云端 Activity、浏览器书签／历史、第三方网站账号和浏览器管理的权限不清理。Telegram 网站只删除 Exts 的专用 IndexedDB，不清除整站数据。数据库连接池与公开 JWKS 缓存不持有用户业务状态，不纳入账号重置。

## 当前存储与运行状态

| 位置 | 当前内容 | 重置动作 |
| --- | --- | --- |
| 扩展 `chrome.storage.local` | `settings`、`downloads`、旧设置键 | 删除扩展本地对象；设置恢复默认，下载记录为空 |
| 扩展 IndexedDB `exts-oidc/credentials` | OIDC 用户、令牌与临时认证状态 | 认证退出成功后清空；下次登录产生的新凭据保留 |
| 扩展来源 `localStorage` | `exts.theme` 主题偏好 | 删除旧偏好，避免设置对象清空后回填旧主题 |
| Telegram 来源 IndexedDB `exts-telegram-download/directory` | Exts 选择的目录句柄 | 在 Telegram 来源定向删除专用数据库或对象，不能使用整站浏览数据清理 |
| 运行中页面与后台 | Activity 展示与视图数据、请求、设置/记录写入、目录句柄、下载流 | 停止旧任务，拒绝旧写入；原地同步账号并清空旧展示 |

当前未发现扩展业务使用 `sessionStorage` 或 CacheStorage；实施时再按引用搜索复核。已保存文件不因删除记录而被删除。

## 单一会话重置入口

后台持有重置锁与当前会话代次。退出或主动登录初始化开始时先切换代次并禁止旧会话业务消息；Activity 请求和各页状态更新在完成前核对代次，不能只比较用户 ID。设置、记录、下载回报在重置期间不得写入旧数据。广播只承担通知；完成判定要等待实际清理结果。

退出的顺序：冻结旧会话并取消可中止任务；等待在途存储写入结束或阻止其回写；清理扩展业务存储与 Telegram 专用目录数据；执行现有刷新令牌撤销和官网会话退出；清除扩展 OIDC 身份；通知所有打开的 Newtab 原地更新账号、Activity 与设置数据，不导航或整体重建页面。任一步失败均返回失败，不提示退出成功；认证尚未清除时保留可重试能力。清理接口应可重复调用，避免一次部分成功使后续重试更危险。

主动登录从未登录状态开始，先执行同一业务重置，再发起 OIDC；认证成功后建立新会话代次并重新请求数据。登录取消或失败不得恢复旧会话数据，也不得误清本次新产生的认证状态。

## Telegram 来源的定向清理

已有 Telegram 页面时先向其隔离脚本发送重置请求，主世界停止当前下载和目录操作、丢弃内存句柄，再由同来源脚本删除 Exts 专用 IndexedDB 并回执。没有可用页面时，可临时打开非活动 Telegram 标签页执行同一操作，完成或失败后关闭临时页。若网站无法加载、删除受其他页面占用、下载无法停止或回执超时，退出失败且不得宣称清理完成。不能以 `chrome.browsingData` 删除整个 Telegram 来源的 IndexedDB 作为降级。

## 失败和验证边界

旧响应不能因相同用户 ID 而通过；下载停止后不能写入记录或继续使用旧句柄。账号与业务状态同步必须覆盖当前页、其他 Newtab 和隐藏的 Home／Studio。清理与认证退出按实际结果报告，失败保留重试路径。

自动化只验证状态与数据边界：同账号新代次、旧请求和下载回写拒绝、清理失败、登录取消、存储清空与重试。真实多标签、Telegram 来源定向删除、下载中止和主题外观由用户在专用 Chrome／Edge 配置文件验收；代理不清除日常浏览器数据。
