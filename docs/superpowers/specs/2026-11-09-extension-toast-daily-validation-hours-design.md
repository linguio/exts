# Activity 小时字段同步设计

## 状态与目标

状态：用户已批准实施，2026-11-10。生产库物理列名仍为 `exercise_minutes` 等五项 `*_minutes`（类型 NUMERIC），单元改为存**小时**；对外 JSON 与排序参数为 `exerciseHours` 等。API 在仓储层做列名映射，不把列重命名为 `*_hours`。

## 已选择方案

公共契约为 `exerciseHours` 等 camelCase 小时字段；值必须为非负 `0.5` 倍数，`0` 合法，`null` 表示未填写。数据库仍使用 `*_minutes` 列名读写相同的小时数值；不做分钟/小时换算，不新增 `*_hours` 物理列。

不执行数据库迁移或数据改写；本工作只改应用映射与校验。

## 交互与边界

Daily Sheet 的五项编辑字段是小时数字输入，最小值 `0`、步进 `0.5`。提交前校验空值、负数和非半小时倍数；后台与 API 以同一规则拒绝绕过界面的非法 JSON。表格单元格和图表直接按小时数展示，统一使用 `h`。

查询排序白名单、API OpenAPI 模型、更新扁平请求体和测试样例都改为 `*Hours`。认证、每日建行、日期字段、Toast 规则、视觉验收和部署均不在本次范围。
