# Telegram Download

Telegram Web 图片、视频右键下载，模块位于 apps/extension/src/modules/tg-download/。在 Telegram 页面取流并流式写入用户选择的文件夹，不连接 Desktop，不额外登录。

## 模块与配置

- components/download-menu：官方 Popover 定位右键操作面板，内部复用官方 Button Group、Button outline 与 DropdownMenu；默认显示下载图标加“下载资源”和横向三点，下拉收起“文件另存为”“选择文件夹”。无常驻目录说明，必要错误时显示恢复文字。
- download-core：媒体保存、Range 写入、文件名、目录目标与 IndexedDB 句柄存储。平台下载逻辑与文件选择都留在 TG 模块。
- page：媒体识别、页面注册、开关/主题接入；文件关闭成功后上报实际文件名和写入字节数，由隔离脚本校验后交给独立 downloads 后台，不上报进行中任务。
- views/settings 与 settings.ts：默认开启，配置保存在 storage.local 的 `settings.telegramDownload.enabled`。关闭立即阻止新下载，正在写入的任务继续；Newtab 只组合功能开关。

仅注入 https://web.telegram.org/*，保留 Telegram Web K 的 .media-viewer-mover 识别边界。开关与主题由隔离环境发布，扩展重载后旧页面入口停用，刷新恢复；不承诺关闭 Telegram 页面后下载继续。

下载入口跟随当前预览层生命周期：预览退出（active 取消或节点移除）时收起按钮组及三点菜单，清除当前目标。仅观察当前预览层及其父节点的直接移除，不轮询或全页扫描；停用时释放观察器。已开始下载持有自身媒体，不因退出预览而中断。

## 快速下载、另存为与重新选择

- 快速下载：首次未配置目录时，在点击栈内打开系统目录选择器，选好并记住后立即保存当前媒体；已有选择时直接保存到该文件夹。取消首次选择不请求媒体、不提示成功。
- 另存为：沿用原有 showSaveFilePicker，保留 telegram-download picker id 与桌面建议位置；独立选择本次文件名和位置，不改变快速下载目录。取消不请求媒体、不提示成功。
- 重新选择：选择或更换后续保存位置，仅记住文件夹，不立即下载；取消或持久化失败保留原选择。
- 不限制名称，不创建 Exts、Telegram 或其他固定子目录。旧版句柄直接作为当前保存目录，不迁移、删除或整理历史文件；若希望继续保存在原子目录，可通过“选择文件夹”选中该子目录。
- 目录选择器建议从 downloads 打开，浏览器可记住上次位置。整个 Downloads、用户根目录等可能被浏览器拒绝授权，用户可以选择普通子目录；这与文件夹名称无关，程序不绕过浏览器限制。
- 目录句柄位于 Telegram 同来源专用 IndexedDB（exts-telegram-download / directory / selected），页面启动时恢复到内存，不放入 chrome.storage.local。首次读取完成前下载操作暂不可用。每次下载在点击栈内请求写权限，持久化不保证永久授权。
- 清除站点数据会移除记住的目录。多个 Telegram 页面各自缓存选择，其他页面刷新后读取最后保存的选择。文件夹删除或权限失效时通过错误文字恢复，不自动重试或切换到其他目录。
- 同名文件/目录采用“文件名 (1).扩展名”递增避重。Web Locks 只保护同来源页面的名称检查与文件占位，实际下载流并行；不保证与外部应用同时创建文件的原子避重。失败可能留下空占位文件，不删除用户文件。
- 浏览器不支持目录选择 API 或锁时，“快速下载”降级为系统另存为，保留原 picker id、桌面建议位置及基础文件名；独立另存为仍可使用，重新选择不可用。

## 写入与完成提示

图片/视频按响应流写入，分段响应继续 Range 请求。只有 writable.close() 成功后显示成功图标与“下载完成”，不附加文件名描述；实际文件名仍写入 Download 记录。开始、进度、失败、取消不弹 Toast。失败时中止写入并记录日志，目录错误只通过菜单提供恢复说明。

完成提示复用 shared/ui/sonner 的共用右下角默认位置，TG 不单独覆盖；多个提示沿用官方折叠行为，不维护全局通知管理。成功记录由独立 modules/downloads 管理，使用 storage.local.downloads.tg.records，并在 Newtab Download 展示；失败或取消不写成功记录。桥接和记录失败只记录错误，不把已成功保存的文件误报为下载失败，不重复弹 Newtab 成功提示。没有 Popup，也不接入 Desktop 或 X 下载。

## 用户验收

- 图片和视频预览中打开入口后，不点下载直接退出，验证按钮组和三点菜单均消失；分别检查关闭按钮、Esc 和重新进入预览，以及已开始下载的文件完整性。

1. Chrome/Edge 重新加载根 dist/build/chrome-mv3，刷新 Telegram Web K，在媒体查看器右键，确认默认显示快速下载及横向三点；横向三点展开另存为、重新选择，检查明暗主题、边缘碰撞、外部点击关闭和键盘操作。
2. 尚未选目录时点击快速下载，选择普通文件夹后当前媒体立即保存，不创建子目录；取消首次选择不下载。已有授权目录时直接保存并检查同名避重。
3. 点击横向三点中的另存为，选择不同文件名与位置，确认流式保存完成、成功记录名称正确；取消不下载；下一次快速下载仍使用原目录。
4. 重新选择只改变后续快速下载位置，不下载当前媒体；取消后仍保留旧位置。刷新、重启或撤销权限后检查目录恢复与授权；目录删除或写入失败不误报完成。
5. 验证图片、大视频文件完整性、连续下载和两个页面并发避重；文件关闭成功后才在右下角显示“下载完成”并生成记录。
6. 检查功能开关与扩展重载：关闭后不启动新任务，已开始的任务继续；旧脚本在扩展重载后停用，刷新恢复。

代理仅验证纯逻辑、类型和构建；系统授权、真实 IndexedDB 克隆/恢复、浏览器重启、磁盘内容及菜单交互由用户验收。用户此前确认整个 Downloads 授权被浏览器拒绝，此限制不因简化菜单而消失。
