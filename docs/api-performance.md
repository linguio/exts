## 资源何时准备

API 进程启动、重启或开发代码自动重载时，lifespan 在后台同时执行两项准备：

1. 借出再归还一次数据库连接，提前完成连接建立，不查 Activity 数据。
2. 获取公开 JWKS，填充正常身份验证使用的同一个公钥缓存，不读取用户令牌。

启动不等待后台准备完成，公开文档可先提供服务。缺少对应配置时跳过准备，预建或预取失败只记录安全告警，业务仍按原路径处理错误。应用退出等待任务收尾并关闭池。

这将准备成本提前，并不消除成本。启动后立即请求、进程重启、网络恢复或资源失效时，业务仍可能等待。当前没有定时保活、周期预取或“准备完成才宣告业务就绪”的机制。

## 连接池的借还

应用连接池复用应用到 Neon 的连接；Neon PgBouncer 复用后端数据库连接。两者不是同一层，使用 pooler 地址不能代替应用连接复用。

当前固定 `psycopg-pool==3.3.3`、`psycopg==3.3.6`，每个进程独立使用：

| 参数 | 当前值与含义 |
| --- | --- |
| min_size / max_size | 0 / 4，不永久强留连接；多进程和多实例需合计容量 |
| timeout | 借用最多等待 5 秒 |
| max_idle | 60 秒，按官方池策略逐步回收，并非恰好第 60 秒全部断开 |
| connect_timeout | 建连超时 5 秒 |

请求结束归还连接，通常不物理断开。未归还、长事务或并发超出容量会导致等待；不能以每次查询后断开来替代归还。损坏连接由官方池淘汰，不自动重放业务操作。未启用每次借用的额外探活查询，隐性断线可能让一次请求返回 503，随后再建立可用连接。

## 事务与公共读取

数据库模块按职责提供三个入口：

- `borrow_connection`：借还连接、数据库错误映射；自身不准备事务。
- `connection`：多步操作或读写任务的显式事务；指定 READ ONLY/READ WRITE，正常退出提交，异常回滚。
- `read_rows`：仓储提供的单次 SELECT。空闲连接上一次发送 BEGIN READ ONLY、事务参数、查询与 COMMIT，返回业务结果；已有事务中只读取，沿用调用者的模式和设置，不擅自提交或回滚。

三个事务本地参数集中维护：Asia/Shanghai、statement_timeout=10000、lock_timeout=5000。官方 ClientCursor 负责参数安全转义，业务 SQL 使用 Composable 和绑定参数，不接受外部用户提供 SQL。连接设置 autocommit=True 是为了避免驱动额外插入 BEGIN，业务仍有显式事务。

单次只读合批减少的是网络等待，不是并行执行 SQL 或取消事务。SQL 失败时批次停止，借还上下文回滚后归还；成功批次的 COMMIT 在服务解释结果前已经完成，因此该入口不能用于“业务校验通过后才允许提交”的写入。需要多步原子操作的服务继续使用 `connection`。

既有事务中读取的分支是实际事务所有权规则，也让读取可以用于已有多步事务；生产代码没有测试执行器、测试模式或假连接分支。

只读检查发现，数据库默认时区为 Asia/Shanghai，但默认 statement_timeout、lock_timeout 均为 0。当前未修改角色、数据库或云端设置，不能直接删除公共超时。事务池也不保证下一事务使用同一后端会话，不能随意将事务设置改成只执行一次的会话设置。

## 身份与权限

每次业务请求仍验证访问 JWT 的允许算法、签名、发行方、受众、期限和用户 ID。公开密钥缓存 300 秒；启动预取不延长缓存，也不改变未知密钥的刷新逻辑。缓存到期、未知密钥或预取失败时，请求仍可能访问认证服务。不缓存认证结果或 Activity 数据。

JWT 的准确有效期由认证服务签发的 exp 决定，仓库未固定时长。访问令牌自身不会延长；扩展在发现过期时尝试用刷新令牌换取新令牌，是否持续有效取决于服务端会话策略。

本地 JWT 验证不能单独确认账号现在是否删除、禁用或会话已撤销。当前 Activity 在一次业务 SQL 中选取用户并外连接本人日期记录：

| 结果 | 含义 | 响应 |
| --- | --- | --- |
| 没有行 | 用户不存在 | 401 |
| 用户存在，关联日期为空 | 该范围无记录 | 200，空数组 |
| 有日期记录 | 本人的数据 | 200，保留 NULL、0、日期及时间戳语义 |

日期 NOT NULL 约束支持空行区分，范围条件放在关联条件中；用户 ID 来自已验证的令牌。删除已提交后，新查询快照中找不到用户即拒绝，不承诺取消已经开始的请求。用户存在也不等于某次会话未撤销；禁用、主动踢出和撤销策略未在本工作项新增。

客户端对 API 401 同步清理登录态的完整流程不在本次性能优化内。讨论中的身份方案不视为用户批准的需求。

## 有效结果与验证边界

| 证据 | 结果 |
| --- | --- |
| 用户实际反馈 | 热请求稳定在约 200ms |
| 同轮、同连接、同请求的原方式 | 558ms、791ms，200 |
| 公共单次只读合批 | 210ms、177ms，200；与原方式响应完全一致，无新建连接 |
| 后台准备样本 | 公钥 615ms、数据库 1401ms，同时完成约 1409ms；随后公钥查找约 0ms |

早期约 8.22 秒的数据库路径先通过连接复用、合并用户判断和事务参数降至一秒内，再通过单次只读合批减少剩余往返。不同轮网络条件存在变化，不能将全部累计改善归因于代码；同轮交替对照是当前主要依据。

诊断使用独立 TestClient 进程，仅在该进程替代 JWT 身份，保留真实数据库操作，不输出凭据或数据、不写数据库。结果不是完整真实 JWT/HTTP/浏览器链路，也不代表所有请求都不超过 300ms。

自动化覆盖认证、日期、NULL/0、空数据、错误响应、资源准备和事务所有权。真实只读验证覆盖响应一致、401/空记录、时区/超时、参数绑定、SQL 错误回滚、干净归还、已有事务保持 INTRANS 和应用退出关闭池。隔离实库测试缺少显式空数据库时跳过，不能记为通过。

仍未验证长期休眠唤醒、持续并发、完整故障恢复及所有冷启动上限；Neon 自身休眠策略未核对。当前不继续增加缓存、封装或保活，后续由具体慢请求和资源需求推动。

普通流水线及显式事务组合曾实测无收益，已移除；当前采用官方简单查询协议合批，不维护实验分支。

## 调试与后续工作

Network Payload 的展开形式由开发者工具控制。前端仍传标准 JSON 对象，不为调试展示改成表单、查询字符串或重复编码；可查看原始请求体确认实际发送内容。

后续优先区分首次/热请求、令牌刷新、公钥获取、建连和业务执行。涉及数据库/角色默认值、部署区域或常驻资源策略的修改，先审阅作用范围再取得批准。对已验证且行为不变的代码复用结果，不以重复测试或增加抽象代替性能证据。
