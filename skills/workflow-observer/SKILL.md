# 开发工作流观察

积累有依据的开发协作观察，帮助后续考察真实需求。观察不是结论，重复不是需求，复盘不要求产出补丁。

## 调用边界

- 先确认正在处理项目开发任务，且用户或当前开发 Skill 明确调用了本 Skill。普通聊天、只打开项目或泛泛提及代码都不触发；已有日志不改变这个边界。
- 仅使用参与当前获准任务时已获得的反馈、行为及结果；不扫描其他聊天、应用、私人活动或未经授权的历史记录，不启动监控。
- 读取目标仓库规则，确认观察日志的写入授权、当前工作项范围与保存位置。Skill 调用本身不授予任意文件写入许可；未获授权时只在本次报告说明可记录的事实，不自行创建持久记录。
- 默认日志为目标项目 docs/skills/workflow-observer/observations.md，有实际材料再创建。项目已有位置时沿用；只记录该项目，不回写安装源目录、个人记忆或其他项目。

## 本次只做需要的动作

- **记录**：保存开发场景、原始事实及来源，区分用户明确要求、代理行为和待考察推测。同一任务的连续小修正可合并为一个有上下文的观察。
- **提醒检查**：在开发阶段收尾按月度规则判断是否值得邀请复盘；无足够观察可跳过，不要求每个任务产生记录。
- **复盘**：用户要求整理时核对证据与反例，可得出继续观察、搁置、否定、修正执行或准备规则修改提案，不自动升级 Skill。

需要写日志、复盘或检查提醒日期时，读取 [记录与复盘规则](references/observation-review.md)。只为回答一般性概念问题时不创建日志。

## 保持观察与需求分开

- 一次选择、频繁重复或个人推测均不能直接写成永久习惯。区分项目约定、临时选择、代理执行问题和可能跨任务成立的模式。
- 补充新证据时保留原始观察含义，注明支持或反对的依据；暂缓或否定事项没有新证据时不重复催促。
- 提案应说明事实依据、适用范围、收益、反例和副作用。修改 Skill、项目规则或个人记忆需另行取得适用授权；观察日志不授予打补丁权限。
- 与 Change 或 Superpowers 配合时只接收已获准开发过程中的事实，不让观察增加实施阶段、审批链或无关测试。

## 月度复盘邀请

仅在开发 Skill 被调用的阶段收尾检查，不是定时任务。首次记录当月先积累；后续自然月有值得考察的未复盘新事实时，每月最多邀请一次。发出邀请与完成复盘分别记录，用户沉默不等于复盘完成；没有新证据不重复催促，不补发未使用月份的提醒。

明确影响当前开发的错误或规则冲突及时报告，不需要等待复盘。只记录实际执行过的动作，不宣称静态指引已经实现后台监测或跨月运行。
