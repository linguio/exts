# 本地变更工作流

帮助当前开发工作形成清晰的范围、真实记录与可审核交付。用户明确指令和目标仓库规则优先；本 Skill 不保存当前任务状态，也不自行建立项目管理体系。

## 使用边界与恢复

- 讨论、问答和只读调查不创建工作项，不启动观察；明确修改指令或对紧邻具体方案的批准才允许相应修改。
- 读取适用 AGENTS、工作台和当前 Issue；检查当前仓库、分支、已有改动及相关提交，只读取本次决策需要的信息。
- 保留用户或其他工作留下的修改。发现未建档改动时先辨明归属和授权，不删除、覆盖、自动暂存或认领。
- 仓库缺少所需规则或工作台时说明缺口；未经批准不搭建新体系。用户批准的操作仍须遵守工具与环境的权限要求。

## 建档与持续推进

- 目标仓库的工作项规则决定目录、字段、阶段及提交格式。没有专门约定时，采用一份 Issue 与一份交付记录，互相链接；默认目录为 docs/changes/issues 与 docs/changes/commits，前缀为 YYYY-MM-DD-project-topic。
- 新工作获批后先建档再实施；模板见 [Issue](assets/issue-template.md) 和 [交付记录](assets/commit-template.md)。小型任务使用足够说明实施与验收的少量 Todo，不因文件多而强制增加 Spec、Plan 或子任务。
- 当前目标的补充或验收修正，按用户明确批准更新范围后继续；独立新目标遵守仓库队列规则。已有批准持续适用于已确认范围，只有缺失信息或范围实质不明时才询问，不因技能切换重复批准。
- 建档完成后、修改代码或配置前，先展示 Issue 链接、已批准范围和唯一下一步。仅建档不等于已展示；已有实施批准时展示后继续，不重复请求确认。
- 收到状态问题时先简短回答，再继续已批准工作；收到明确暂停、取消或替换目标时遵循用户最新指令。
- Issue 只维护当前有效范围、未完成事项及下一步；交付记录收尾时整理成最终结果、有效验证和限制，替换过时结论，保留真正影响判断的失败证据。

## 验收与提交

- 验证围绕当前行为和真实风险，沿用仓库要求；结果通过不等于用户验收。完成后展示交付、实际验证、未验证事项及可复现验收步骤。
- 用户只表示验收通过时，按仓库规则进入待提交；用户明确要求“提交到本地”即表示当前 Issue 可以完结并批准提交，不以用户是否实际验证、提供验证细节或看过交付材料为前提。不追问验证、不重复请求验收、不追加验证；在本地提交中同步 Issue、Commit 记录和工作台为已完成。未执行的检查只如实记录，不阻止完结；提交失败时恢复待提交状态。
- “拆分 Commit”表示准备文件边界和完整消息，不自动表示允许提交。默认一个完整交付；多笔提交须明确边界，最后一笔同步工作项终态。
- 提交前展示或已经展示文件、diff 摘要、验证与限制、每笔完整消息及机械性终态更新。批准后只执行该范围；未经批准的其他变化不能混入原提交。
- 提交收尾只做已批准的终态记录同步、待提交 diff 与消息核对、本地提交和结果汇报。验证已完成且相关内容未变化时复用已有结果，不为提交重跑全量测试、类型检查或构建，不重新展开调查或引入其他工作。用户已批准范围和消息时直接执行，不重复请求验收或提交确认。
- 用户明确要求不再验证时遵从，记录沿用结果及未验证事项，不以 Skill 流程为由补跑测试、模拟场景或子代理，也不把未执行的检查写成通过。
- 拆分已有提交前先核对本地与远端状态，说明每笔文件边界、完整消息及同步影响。原提交已在远端时，明确本地重写会造成历史分叉、普通推送无法同步；本地拆分批准不包含远端覆盖，后者须单独取得明确批准，并使用带已知远端提交限制的 force-with-lease，远端变化时停止覆盖。
- 提交前核对暂存内容和待用消息；正文采用真实 LF，可使用 -F 文件或实际换行参数。提交后核对实际消息、相关记录和 git status；不自动推送、发布、amend 或重写历史。
- 提交失败时保留成功结果，恢复未完成部分的真实状态，按仓库要求处理批准字段；不自动回滚已完成提交或重新提交成功部分。

创建、恢复、处理范围分歧或提交异常时，按需读 [流程参考](references/workflow.md)。

## 与 Superpowers 等专项技能配合

- 按实际问题使用设计、计划、排错、实现、审查或验证技能。Superpowers 可提供对应方法；已有 Issue、设计和必要 Plan 共用，不重复建档或自动增加阶段。
- 用户与仓库规则决定是否允许子代理、并行任务、视觉验证及 Git 操作。专项技能提出这些步骤不代表已经获准；冲突时采用符合现有授权的方式并如实说明限制。
- 专项技能不可用时，本流程仍能执行；只有实际阻塞当前交付时才说明缺口，不为了形式安装新工具。

## 开发观察入口

只在正在执行本开发流程的阶段收尾节点检查是否存在值得记录的开发事实或待复盘记录。按需读取配套 [workflow-observer](../workflow-observer/SKILL.md)，仅执行本次需要的记录或复盘检查。

日志写入必须符合目标项目已有授权及工作项范围。没有授权不自行持久化；配套 Skill 不可用时继续开发，不自动安装。普通聊天和纯问答不进入此入口，已有日志也不能让观察在普通聊天中自动运行。
